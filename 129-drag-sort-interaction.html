第一百二十九部分 · 拖拽与排序交互——指针状态机、排序模型与三大库实战 ​

本册把「拖拽」拆成四层：指针输入 → 拖拽状态 → 命中测试 → 排序数据。4px 阈值与指针捕获的基础模型见 45.3.4 拖拽的 4px 阈值与指针捕获；长列表拖拽必须与 10.4 高性能虚拟列表 协同；表格行拖拽可对照 64.1 虚拟滚动内核；文件拖入与上传见 19.6 文件校验、下载与剪贴板。

技术基线（2025-11）：sortablejs 1.15.x、vuedraggable 4.1.x（Vue 3）、@dnd-kit/core 6.x + @dnd-kit/sortable 10.x、@hello-pangea/dnd 17.x/18.x。dnd-kit 与 hello-pangea 的大版本迭代较快，正文对可能变化的 API 均标注「以安装版本为准」。

四个配套示例全部纯 TS、零 DOM，node:assert 硬断言，可 npx tsx 实跑；React/Vue 片段标注「项目内运行」。

129.1 心智模型：拖拽不是「拖动 DOM」，而是「状态 + 数据」 ​

很多实现一开始就写 onmousemove 改 style.left/top，最后必然遇到：点击被误判成拖拽、移动端不触发、拖出容器后失灵、松手位置和排序结果对不上。把拖拽拆成四层，问题会各归其位：

层职责典型实现
输入层统一鼠标/触摸/触控笔；处理阈值与取消Pointer Events + setPointerCapture
状态层idle → pressed → dragging → dropped/cancelled有限状态机（示例 129-01）
命中层当前指针落在哪个可放置目标closestCenter / pointerWithin / rectIntersection
数据层根据 from/to 重排数组或跨容器迁移arrayMove / transfer（示例 129-02/03）

输入层：为什么用 Pointer Events ​

事件模型鼠标触摸触控笔统一坐标结论
Mouse Events✅❌部分❌移动端不可用
Touch Events❌✅部分多指复杂只做兜底
HTML5 Drag and Drop✅❌（移动端基本不支持）❌受限只适合桌面文件拖入
Pointer Events✅✅✅✅ clientX/Y首选

Pointer Events 的关键 API：

ts
// [浏览器] 项目内运行
el.addEventListener('pointerdown', (e) => {
  if (e.button !== 0) return;                 // 只响应主键
  el.setPointerCapture(e.pointerId);          // 把后续 move/up 锁定到该元素
  // 之后即使指针移出元素，pointermove / pointerup 仍派发给 el
});
el.addEventListener('pointermove', onMove);
el.addEventListener('pointerup', onUp);
el.addEventListener('pointercancel', onCancel); // 系统手势/来电等打断

setPointerCapture 解决的是「快速拖动时指针离开元素，move 事件丢失」；pointercancel 必须处理，否则移动端被系统手势打断后状态永远停在 dragging。

坐标系：别混用 client/page/screen/offset ​

坐标相对谁用途
clientX/Y视口指针位置、命中测试（推荐）
pageX/Y文档（含滚动）需要跨滚动计算时
screenX/Y屏幕极少用
offsetX/Y目标元素内边距不适合拖拽，目标会变

统一用 clientX/Y + getBoundingClientRect()；滚动容器的偏移单独加，不要在事件之间来回换算。

4px 阈值：区分「点击」与「拖拽」 ​

手指/鼠标按下时都有微小抖动。没有阈值，用户想点击却被判定为拖拽，click 也会丢失。行业常用 4~8px：

  • 小于阈值：保持 pressed，不改变样式、不阻止点击；
  • 超过阈值：进入 dragging，此时才 preventDefault 并显示拖拽态；
  • 阈值判断用欧氏距离 Math.hypot(dx, dy)，不要只看单轴。

129.2 原生最小实现：从 pointerdown 到 transform ​

ts
// 文件: examples/129-01-drag-state-machine.ts（节选）
pointerMove(current: Point, pointerId = 1): DragState {
  if (this.state.phase !== 'pressed' && this.state.phase !== 'dragging') return this.state;
  if (this.state.phase === 'pressed') {
    const dx = current.x - this.state.start.x;
    const dy = current.y - this.state.start.y;
    if (Math.hypot(dx, dy) < this.config.threshold) return this.state; // 阈值内仍视为点击
    if (this.state.pointerId !== pointerId) return this.state;           // 多指隔离
    this.state = { phase: 'dragging', start: this.state.start, current, offset: { x: 0, y: 0 } };
  }
  let offset = { x: current.x - this.state.start.x, y: current.y - this.state.start.y };
  if (this.config.axis === 'x') offset = { x: offset.x, y: 0 };
  if (this.config.axis === 'y') offset = { x: 0, y: offset.y };
  offset = this.clamp(offset);
  this.state = { phase: 'dragging', start: this.state.start, current, offset };
  return this.state;
}

运行方式：npx tsx examples/129-01-drag-state-machine.ts（实跑；断言覆盖阈值、轴锁、边界钳制、取消、pointerId 隔离）

把它接到 DOM 上，只需要三件事：

ts
// [浏览器] 项目内运行：最小可拖拽元素
let start: { x: number; y: number } | null = null;

el.style.touchAction = 'none'; // 关键：阻止移动端滚动抢走手势
el.addEventListener('pointerdown', (e) => {
  if (e.button !== 0) return;
  start = { x: e.clientX, y: e.clientY };
  el.setPointerCapture(e.pointerId);
});

el.addEventListener('pointermove', (e) => {
  if (!start) return;
  const dx = e.clientX - start.x;
  const dy = e.clientY - start.y;
  if (Math.hypot(dx, dy) < 4) return;
  // ✅ 只改 transform，不碰 left/top，避免每帧触发布局
  el.style.transform = `translate3d(${dx}px, ${dy}px, 0)`;
});

el.addEventListener('pointerup', () => {
  start = null;
  el.style.transform = '';
});

三个必须补的工程细节：

  1. touch-action: none：否则移动端浏览器会把手势判为滚动，pointermove 中途被 pointercancel；只想锁定单轴时用 touch-action: pan-y / pan-x；
  2. pointercancel：系统返回手势、来电、通知下拉都会触发，必须把状态复位；
  3. preventDefault 的时机：在 pointerdown 就阻止会破坏输入框聚焦与点击；应在超过阈值、确认拖拽后再阻止。

自动滚动：拖到容器边缘时页面要跟着滚 ​

ts
// [浏览器] 项目内运行：边缘自动滚动（rAF 循环）
function autoScroll(container: HTMLElement, clientY: number, speed = 12) {
  const rect = container.getBoundingClientRect();
  const edge = 48;
  if (clientY < rect.top + edge) container.scrollTop -= speed;
  else if (clientY > rect.bottom - edge) container.scrollTop += speed;
}
// 在 pointermove 里调用；拖拽结束后 cancelAnimationFrame

注意：自动滚动会改变 getBoundingClientRect()，拖拽开始时缓存的矩形会过期。长列表要每帧重新测量可视区目标，或至少监听 scroll 更新缓存。

129.3 排序模型：索引语义是 80% bug 的来源 ​

拖拽排序最终都落到一个操作：arrayMove(items, from, to)。

ts
// 文件: examples/129-02-array-move.ts（节选）
export function arrayMove<T>(items: readonly T[], from: number, to: number): T[] {
  if (from === to) return [...items];
  if (from < 0 || from >= items.length) throw new RangeError(`from 越界：${from}`);
  if (to < 0 || to >= items.length) throw new RangeError(`to 越界：${to}`);
  const next = [...items];
  const [moved] = next.splice(from, 1);
  next.splice(to, 0, moved);
  return next;
}

运行方式：npx tsx examples/129-02-array-move.ts（实跑；断言覆盖单元素、多选、跨容器、越界与不可变更新）

三种索引口径，绝不能混 ​

来源to 的含义示例（[a,b,c,d]，拖 b 到 d 之后）
dnd-kit arrayMove移除后的最终下标arrayMove(items, 1, 3) → [a,c,d,b]
SortableJS onEndoldIndex/newIndex 也是最终下标newIndex = 3
自定义「插入到某元素之前」原始数组下标，向下拖要减 1over=3 → insertAt=2 → [a,c,b,d]

如果你发现「拖到下一格却跳过一格」「向下拖永远差一位」，几乎一定是把第三种口径当成第一种用了。先确定你的命中层输出哪种口径，再写唯一的转换函数。

跨容器与多选 ​

  • 跨容器：先 splice 源数组，再 splice 目标数组；目标插入下标要基于「移除后」的长度做钳制；
  • 多选移动：先收集选中项，再从剩余项计算插入点。插入点 = target - 原数组中位于 target 之前的选中项数量，否则会整体偏移；
  • 不可变更新：返回新数组，别原地 splice，否则 React/Vue 的引用比较失效，拖完不刷新；
  • 稳定 id：key 必须用业务 id，不能用数组下标；拖拽过程中下标一直在变，下标 key 会让 DOM 节点错位、输入框内容串行。

跨组规则：pull / put / clone ​

ts
// 文件: examples/129-03-sortable-reorder.ts（节选）
export function canDrop(board: Board, itemId: string, from: string, to: string): boolean {
  const item = board.groups[from]?.find((i) => i.id === itemId);
  if (!item || item.disabled) return false;
  if (from === to) return true;
  const src = board.rules[from];
  const dst = board.rules[to];
  if (!src || !dst) return false;
  return src.pull !== false && dst.put === true;
}

运行方式：npx tsx examples/129-03-sortable-reorder.ts（实跑；断言覆盖禁用项、只进不出、clone 保留源、键盘排序跳过禁用项、重复 id 检测）

业务上至少要区分四类规则：

  1. 自由移动：pull: true, put: true；
  2. 只进不出：pull: false, put: true（如「已完成」列）；
  3. 只出不进：pull: true, put: false（如「待办」列不允许外部拖入）；
  4. 克隆：pull: 'clone', put: true（组件面板拖到画布，源元素保留，克隆体要换新 id）。

129.4 SortableJS 真讲：最省事的 DOM 排序库 ​

SortableJS 直接操作真实 DOM，不依赖框架，适合「已有列表，只想加拖拽」的场景。

ts
// [项目内运行] npm i sortablejs@1.15
import Sortable from 'sortablejs';

const sortable = new Sortable(listEl, {
  animation: 150,                 // 位移动画时长 ms
  handle: '.drag-handle',         // 只有把手可拖，避免误触
  draggable: '.task',             // 可拖项选择器
  ghostClass: 'task-ghost',       // 占位符样式
  chosenClass: 'task-chosen',
  dragClass: 'task-drag',
  group: { name: 'tasks', pull: true, put: true },
  swapThreshold: 0.65,            // 交换阈值，越小越"跟手"
  invertSwap: false,
  forceFallback: true,            // 不使用原生 HTML5 DnD，统一行为（移动端更稳）
  fallbackOnBody: true,           // 拖拽克隆挂到 body，避免被 overflow 裁剪
  fallbackTolerance: 4,           // 4px 阈值
  scroll: true,                   // 容器边缘自动滚动
  scrollSensitivity: 80,
  scrollSpeed: 12,
  onStart(evt) {
    console.log('开始拖', evt.oldIndex, evt.from);
  },
  onMove(evt) {
    // 返回 false 可禁止放到某个目标
    return !evt.related.classList.contains('no-drop');
  },
  onEnd(evt) {
    const { oldIndex, newIndex, from, to } = evt;
    if (oldIndex == null || newIndex == null) return;
    // ⚠️ SortableJS 已经移动了真实 DOM；React/Vue 受控列表要在这里同步数据，
    //    否则下一次 render 会把 DOM 还原，出现"闪回"。
    if (from === to) setItems((prev) => arrayMove(prev, oldIndex, newIndex));
    else transferBetween(from, to, oldIndex, newIndex);
  },
});

// 销毁：SPA 路由切换/组件卸载必须调用，否则监听器与克隆节点残留
sortable.destroy();

多选拖拽要换构建产物 ​

multiDrag、Swap、OnSpill 是插件，不在默认完整包里：

ts
// 需要插件时改用 complete 构建
import Sortable from 'sortablejs/modular/sortable.complete.esm.js';

new Sortable(el, {
  multiDrag: true,
  selectedClass: 'selected',
  avoidImplicitDeselect: true,
});

只 import sortablejs 却写 multiDrag: true，不会报错，只是静默不生效——这是最常见的「配置了没反应」。

SortableJS 的边界 ​

  • 它直接改 DOM：与 React/Vue 的受控渲染天然冲突，必须在 onEnd 同步数据，且列表要 key 稳定；
  • 嵌套列表要分别初始化，并用 group 与 onMove 控制；
  • 虚拟列表只渲染可视项时，跨屏拖拽需要自己处理「拖到边缘加载更多」；
  • 表格行拖拽要小心 <tbody> 结构与 display: table-row 的 transform 兼容性。

129.5 vuedraggable：Vue 3 的声明式封装 ​

vuedraggable@4 基于 SortableJS，提供 v-model 与插槽：

vue
<!-- [项目内运行] npm i vuedraggable@4 sortablejs -->
<script setup lang="ts">
import draggable from 'vuedraggable';
import { ref } from 'vue';

interface Task { id: string; name: string }
const list = ref<Task[]>([
  { id: '1', name: '写方案' },
  { id: '2', name: '评审' },
]);

function onEnd(evt: { oldIndex: number; newIndex: number }) {
  console.log('排序完成', evt.oldIndex, evt.newIndex);
}
</script>

<template>
  <draggable
    v-model="list"
    item-key="id"
    group="tasks"
    handle=".handle"
    ghost-class="ghost"
    :animation="150"
    @end="onEnd"
  >
    <template #item="{ element, index }">
      <div class="task">
        <span class="handle">⋮⋮</span>
        <span>{{ index + 1 }}. {{ element.name }}</span>
      </div>
    </template>
  </draggable>
</template>

要点：

  • item-key 必须是稳定 id，不能用 index；
  • v-model 已经处理了组内排序，@end 只用于跨组同步或埋点；
  • 跨组拖拽用 group 对象（{ name, pull, put }），接收方也要有相同的 group.name；
  • Vue 3 必须用 v4，v3 只支持 Vue 2；vuedraggable@next 是旧别名，安装时确认版本。

129.6 dnd-kit 真讲：React 的现代选择 ​

dnd-kit 不直接改 DOM，而是提供 transform 让你自己渲染，天然适配 React 受控模型、虚拟列表与自定义传感器。

最小可排序列表 ​

tsx
// [项目内运行] npm i @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities
import {
  DndContext, DragOverlay, PointerSensor, KeyboardSensor,
  closestCenter, useSensor, useSensors,
} from '@dnd-kit/core';
import {
  SortableContext, arrayMove, sortableKeyboardCoordinates,
  useSortable, verticalListSortingStrategy,
} from '@dnd-kit/sortable';
import { CSS } from '@dnd-kit/utilities';
import { useState } from 'react';

function SortableItem({ id, label }: { id: string; label: string }) {
  const { attributes, listeners, setNodeRef, transform, transition, isDragging } = useSortable({ id });
  const style = {
    transform: CSS.Transform.toString(transform),
    transition,
    opacity: isDragging ? 0.4 : 1,
  };
  return (
    <div ref={setNodeRef} style={style} {...attributes} {...listeners}>
      {label}
    </div>
  );
}

export function TaskList() {
  const [items, setItems] = useState([
    { id: '1', label: '写方案' },
    { id: '2', label: '评审' },
    { id: '3', label: '开发' },
  ]);
  const [activeId, setActiveId] = useState<string | null>(null);
  const sensors = useSensors(
    useSensor(PointerSensor, { activationConstraint: { distance: 4 } }),
    useSensor(KeyboardSensor, { coordinateGetter: sortableKeyboardCoordinates }),
  );

  return (
    <DndContext
      sensors={sensors}
      collisionDetection={closestCenter}
      onDragStart={({ active }) => setActiveId(String(active.id))}
      onDragEnd={({ active, over }) => {
        setActiveId(null);
        if (!over || active.id === over.id) return;
        setItems((prev) => {
          const from = prev.findIndex((i) => i.id === active.id);
          const to = prev.findIndex((i) => i.id === over.id);
          return arrayMove(prev, from, to);
        });
      }}
      onDragCancel={() => setActiveId(null)}
    >
      <SortableContext items={items.map((i) => i.id)} strategy={verticalListSortingStrategy}>
        {items.map((item) => <SortableItem key={item.id} {...item} />)}
      </SortableContext>
      <DragOverlay>
        {activeId ? <div className="overlay">{items.find((i) => i.id === activeId)?.label}</div> : null}
      </DragOverlay>
    </DndContext>
  );
}

dnd-kit 的核心概念 ​

概念作用常见坑
DndContext提供拖拽上下文与事件多个列表要共享拖拽时，必须放在同一个 Context 内
useDraggable / useDroppable自由拖拽与放置区不要与 useSortable 混用于同一元素
useSortable可排序项，内置 transform/transitionsetNodeRef 必须挂到真实节点
SortableContext声明排序范围与策略items 必须是稳定 id 数组
sensors输入方式与激活约束不配 PointerSensor 的 distance，点击按钮会误拖
collisionDetection命中算法嵌套容器用 closestCenter 可能选到父级
DragOverlay拖拽浮层，避免被 overflow: hidden 裁剪不使用时拖动元素可能被容器裁掉
arrayMove官方重排工具to 是最终下标，别再做 ±1

跨容器 ​

两个容器共享一个 DndContext，每个容器一个 SortableContext；在 onDragEnd 里判断 active 与 over 所属容器：

tsx
// [项目内运行] 伪代码：跨列看板
const from = findContainer(active.id); // 自己维护 id → 列 的映射
const to = over ? findContainer(over.id) : null;
if (!to) return;
if (from === to) reorderInColumn(from, active.id, over.id);
else moveBetweenColumns(from, to, active.id, over.id);

容器本身也要 useDroppable，否则拖到空列时 over 为 null，无法放入。

版本与 React 兼容 ​

  • @dnd-kit/core 6.x、@dnd-kit/sortable 10.x 是 2025 年的主流组合；
  • React 19 项目安装前先看 peerDependencies，必要时用 --legacy-peer-deps 或等待官方版本；
  • 不同大版本之间 useSortable 返回值与 CSS.Transform 用法可能有调整，以安装版本的 README 为准。

129.7 react-beautiful-dnd 的现状与迁移 ​

结论：新项目不要再用 react-beautiful-dnd。 Atlassian 已停止维护并归档该仓库，React 18 严格模式/React 19 下存在兼容问题，也不再修复。

方案关系迁移成本建议
@hello-pangea/dnd社区维护的 drop-in 分支低：改 import 包名已有 rbd 代码、想最小改动
@dnd-kit另一套现代实现中：重写组件结构新项目、需要自定义传感器/虚拟列表
react-dnd基于 HTML5 后端的老牌库中特殊后端需求，生态不如 dnd-kit 活跃

@hello-pangea/dnd 的 API 与 rbd 基本一致（DragDropContext、Droppable、Draggable、onDragEnd 的 source/destination），但它不是「永久兼容承诺」，长期仍建议评估 dnd-kit。

129.8 命中测试：拖到哪个位置才算数 ​

排序结果由「命中哪个目标」决定。三种常用算法：

算法规则适合风险
closestCenter指针到各目标中心点距离最近等高列表、网格嵌套容器时可能选到父级
pointerWithin指针落在矩形内，取面积最小嵌套容器、精确放置指针在空隙时无命中
rectIntersection拖拽矩形与目标相交面积最大卡片高亮、自由布局大面积容器容易霸榜
ts
// 文件: examples/129-04-collision-detect.ts（节选）
export function pointerWithin(pointer: Point, entries: CollisionEntry[]): string | null {
  const hits = entries.filter(
    (e) => !e.disabled && pointer.x >= e.rect.left && pointer.x <= e.rect.left + e.rect.width &&
      pointer.y >= e.rect.top && pointer.y <= e.rect.top + e.rect.height,
  );
  if (hits.length === 0) return null;
  return hits.sort((a, b) => a.rect.width * a.rect.height - b.rect.width * b.rect.height)[0].id;
}

运行方式：npx tsx examples/129-04-collision-detect.ts（实跑；断言覆盖三种算法、禁用项、嵌套容器、空白区与无命中）

工程建议：

  1. 列表排序用 closestCenter，阈值稳定、不会因为间隙出现「无目标」；
  2. 嵌套容器用 pointerWithin，并优先选面积最小的目标；
  3. 矩形测量在拖拽开始时缓存，拖拽中只做坐标比较；自动滚动后要更新缓存；
  4. 空容器也要注册 droppable，否则永远拖不进去；
  5. 禁用项不参与命中，并且在视觉上明确「不可放置」。

129.9 性能、边界与无障碍 ​

渲染性能 ​

  • 只改 transform：translate3d 走合成层，不触发布局；改 top/left 每帧 Layout + Paint；
  • 避免 layout thrash：不要在 pointermove 里读 offsetTop、getBoundingClientRect 后再写样式，读写分离；
  • will-change: transform 慎用：拖拽开始时加、结束移除，长期挂着会浪费显存；
  • 拖拽浮层用 position: fixed + pointer-events: none，避免浮层自己参与命中；
  • 虚拟列表：只渲染可视项时，拖拽跨越未渲染区域要靠自动滚动 + 占位符；SortableContext 的 items 仍应是完整 id 列表。

移动端 ​

  • touch-action: none 只加在拖拽把手上，别整页加，否则页面无法滚动；
  • 长按 300~500ms 进入拖拽可以避免与滚动冲突，但会牺牲「立即跟手」；
  • 拖拽时禁止页面滚动：overflow: hidden 要记录原值并在结束后恢复；
  • iOS Safari 的 pointercancel 更频繁，必须有取消态。

无障碍（a11y） ​

  • 提供键盘排序：dnd-kit 的 KeyboardSensor + sortableKeyboardCoordinates；自研实现至少支持 Alt+↑/↓；
  • 提供「上移/下移」按钮，保证无法拖拽的用户也能操作；
  • 拖拽过程用 aria-live 播报「已移动到第 3 项」；
  • 不要依赖颜色区分拖拽态，补充图标/文本；
  • 焦点管理：拖拽结束后焦点回到被移动项。

与表单/表格的协同 ​

  • 可编辑表格的行拖拽，key 必须用行 id；拖拽结束后要重新校验行号相关字段；
  • 拖拽期间不要触发输入框的 blur 校验，否则会刷一屏错误；
  • 树形拖拽要定义「放到节点前/后/内部」三种落点，不能只用一个 over；
  • 文件拖入（dragover/drop）与元素拖拽是两套 API，不要混用 dataTransfer 与 Pointer Events。

129.10 自测题 ​

1. 为什么拖拽排序优先用 Pointer Events 而不是 Mouse/Touch Events？【基础】

Pointer Events 用一套 API 统一鼠标、触摸、触控笔，坐标体系统一（clientX/Y），并支持 setPointerCapture 与 pointercancel。Mouse Events 不支持触摸；Touch Events 不支持鼠标且多指处理复杂；HTML5 DnD 在移动端基本不可用。

2. 4px 阈值解决什么问题？为什么不能只看单轴？【基础】

区分「点击」与「拖拽」，避免手指/鼠标抖动把点击误判为拖拽。单轴判断会漏掉斜向移动，应该用 Math.hypot(dx, dy) 计算欧氏距离；阈值内保持 pressed，不阻止点击。

3. `setPointerCapture` 与 `pointercancel` 各解决什么问题？【基础】

setPointerCapture 把后续 pointermove/up 锁定到元素，快速拖动移出元素也不丢事件；pointercancel 处理系统手势、来电等打断，必须复位状态，否则界面永远停在拖拽态。

4. `arrayMove(from, to)` 的 `to` 到底是什么下标？【进阶】

在 dnd-kit 与 SortableJS 的口径里，to 是「先移除 from、再插入」后的最终下标，直接用即可。如果命中层返回的是「插入到某元素之前」的原始下标，向下拖必须减 1。三种口径混用会出现「差一格/跳一格」。

5. 为什么拖拽列表的 key 不能用数组下标？【进阶】

拖拽过程中下标持续变化，React/Vue 会按 key 复用节点，导致 DOM 与数据错位、输入框内容串行、动画错乱。必须用稳定的业务 id。

6. SortableJS 已经移动了真实 DOM，为什么 React/Vue 还会「闪回」？【进阶】

受控渲染下一次 render 会按旧数据重建 DOM，把 SortableJS 的改动覆盖掉。必须在 onEnd 里同步更新数据（不可变数组），让框架状态与 DOM 一致；同时保证 key 稳定。

7. dnd-kit 的 `SortableContext`、`useSortable`、`DragOverlay` 各负责什么？【挑战】

SortableContext 声明排序范围与策略并提供 id 列表；useSortable 给单项提供 setNodeRef、listeners、attributes、transform/transition；DragOverlay 渲染拖拽浮层，避免被 overflow: hidden 裁剪，并让原位置保留占位。

8. 嵌套容器为什么 `closestCenter` 容易选错？怎么解？【挑战】

父容器面积大、中心点可能比子项更接近指针，导致命中父级。应改用 pointerWithin，并优先选择面积最小（最具体）的目标；同时确保空容器也注册 droppable，否则拖不进去。

9. 虚拟列表里的拖拽要做哪些额外处理？【挑战】

只渲染可视项，跨屏拖动需要边缘自动滚动 + 动态渲染；SortableContext 的 items 仍要是完整 id 列表；拖拽开始时缓存矩形、滚动后更新；占位符要固定高度，避免列表抖动；必要时用 DragOverlay 脱离滚动容器。

10. 无障碍拖拽的最低要求是什么？【挑战】

提供键盘排序（dnd-kit 的 KeyboardSensor 或 Alt+↑/↓）、提供上移/下移按钮、用 aria-live 播报位置变化、拖拽结束恢复焦点、不要只靠颜色表达状态。快捷键是增强，不是唯一入口。
