102.1 三大框架定位与选型 ​

概念解析 ​

Element Plus 是 Element UI 的 Vue 3 版本，是 B 端管理后台的事实标准——GitHub 15k+、npm 周下载量 600k+、覆盖 70+ 组件、中文文档原生、内部企业级业务场景沉淀最多。

Ant Design Vue 是蚂蚁金服 Ant Design 设计体系的 Vue 实现，组件数略少但设计规范更精细，适合对视觉一致性和无障碍（a11y）有更高要求的国际化项目。

Vant 是有赞出品的移动端轻量组件库，体积小、API 简洁、适配 H5/小程序/快应用，是移动端 H5 场景的首选。

维度Element PlusAnt Design VueVant
定位B 端管理后台 / 中后台企业级 / 国际化移动端 H5 / 小程序
组件数~80~60~60
体积（按需引入）~80KB（Gzip）~60KB（Gzip）~40KB（Gzip）
设计体系ElementAnt DesignVant
Vue 版本Vue 3Vue 3Vue 2 / Vue 3 共存
移动端支持需额外适配需额外适配原生适配
暗黑模式原生支持原生支持原生支持

应用实践 ​

  • 新项目默认 Element Plus，除非有明确的 Ant Design 设计规范要求或移动端为主的场景
  • 项目中同时存在 PC 后台 + 移动端 H5 时，PC 侧用 Element Plus，移动端用 Vant（不要强行用同一框架覆盖两端——Element Plus 的组件尺寸在移动端体验很差）
  • 选型前先做打包体积预算测试：引入框架基础组件后看 vendor chunk 增量，按需导入下 Element Plus 约 80KB，Ant Design Vue 约 60KB，Vant 约 40KB

102.2 Element Plus 接入闭环 ​

概念解析 ​

Element Plus 接入最常见的失败是把"写了 import"误当成"库已被工程正确集成"——依赖声明、入口注册、样式入口、按需导入、图标策略，任何一环缺失都会在构建期或运行期暴露。正确姿势是选定唯一方案 + 补齐所有闭环：

两条路线二选一：

路线适用场景体积复杂度
全量注册中小项目、不追求极致体积、快速接入大（约 200KB Gzip）低（一行 app.use(ElementPlus)）
按需自动导入组件使用面广、追求体积优化、生产级项目小（约 80KB Gzip）中（Vite 双插件配置）

按需自动导入三件套（最常用的生产方案）：

ts
// vite.config.ts —— 用 unplugin-vue-components + unplugin-auto-import
// 双插件共享 ElementPlusResolver，同时解决"模板组件"和"组合式 API"的自动导入
import AutoImport from "unplugin-auto-import/vite";
import Components from "unplugin-vue-components/vite";
import { ElementPlusResolver } from "unplugin-vue-components/resolvers";

export default defineConfig({
  plugins: [
    vue(),
    // 自动导入 ElMessage、ElNotification 等组合式 API
    AutoImport({ resolvers: [ElementPlusResolver()] }),
    // 自动识别模板中的 <el-button> <el-form> 等标签
    Components({ resolvers: [ElementPlusResolver()] }),
  ],
});

样式入口（按需导入下仍需全局引入一次）：

ts
// main.ts —— 全局样式只从一个地方进入，避免多组件分散引入
import "element-plus/dist/index.css";
import { createApp } from "vue";
import App from "./App.vue";
const app = createApp(App);
app.mount("#app");

依赖声明：element-plus + @element-plus/icons-vue（按需导入图标时也走同一个 resolver）。

完整代码示例 ​

ts
// 文件: examples/102-01-element-plus-config.ts（节选：配置生成器）
// 生成按需导入配置 + 校验依赖清单闭环（防止"写了 import 但 package.json 缺失"）
interface ElementPlusDeps {
  "element-plus": string;
  "@element-plus/icons-vue": string;
  "unplugin-auto-import": string;
  "unplugin-vue-components": string;
  vite: string;
}

function generateViteConfig(
  mode: "full" | "auto",
  icons: boolean = true,
): { configSnippet: string; missingDeps: string[] } {
  const required: Partial<Record<ElementPlusDeps, boolean>> = {
    "element-plus": true,
    vite: true,
  };
  if (mode === "auto") {
    required["unplugin-auto-import"] = true;
    required["unplugin-vue-components"] = true;
  }
  if (icons) required["@element-plus/icons-vue"] = true;

  // 真实项目里从 package.json 读取；此处用 mock
  const declared: string[] = ["element-plus@2.7.0", "vite@5.0.0", "@element-plus/icons-vue@2.3.1"];
  const declaredKeys = new Set(declared.map((d) => d.split("@")[0]));
  const missing = Object.keys(required).filter((k) => !declaredKeys.has(k));

  let snippet = "";
  if (mode === "full") {
    snippet = `// 全量注册：main.ts 一行搞定（体积大，适合中小型项目）
import ElementPlus from "element-plus";
app.use(ElementPlus);`;
  } else {
    snippet = `// 按需自动导入：vite.config.ts
// 双插件共享 ElementPlusResolver，模板组件 + 组合式 API 自动识别
import AutoImport from "unplugin-auto-import/vite";
import Components from "unplugin-vue-components/vite";
import { ElementPlusResolver } from "unplugin-vue-components/resolvers";

plugins: [
  vue(),
  AutoImport({ resolvers: [ElementPlusResolver()] }),  // ElMessage 等 API
  Components({ resolvers: [ElementPlusResolver()] }),   // <el-button> 等模板标签
],`;
  }

  return { configSnippet: snippet, missingDeps: missing as string[] };
}

运行方式：npx tsx examples/102-01-element-plus-config.ts

应用实践 ​

  • 只选一条路线：不要同时做全量注册和按需导入——两套方式并存会导致 tree-shaking 失效、样式策略冲突
  • 样式入口唯一性：element-plus/dist/index.css 只在 main.ts 引入一次，组件内不要再 import "element-plus/es/components/xxx/style/css"，避免 HMR 时样式重复注入
  • 图标策略与依赖一致：如果用了 @element-plus/icons-vue，就在 resolver 里打开，不要全局注册后又按需引入

102.3 el-form 校验封装 ​

概念解析 ​

el-form + Schema 驱动是 B 端表单开发的标准范式——把字段定义（label / 类型 / 校验规则 / 占位符）收敛成一份配置，el-form 的 :rules 直接消费，低代码表单引擎（衔接 38 册）可在此基础上扩展。

校验规则三种来源：

  1. el-form 内置规则（required / pattern / type: 'email'）
  2. 自定义校验函数（validator: (rule, value, cb) => ...）
  3. 外部 schema 库（Zod / Yup）与 el-form 规则互转（衔接 33 册）

经典坑：el-form 规则的 trigger 语义——el-form 有两种触发时机：blur（失焦）、change（值变化），表单元素类型决定默认 trigger，但自定义校验函数的 trigger 必须显式指定，否则可能在错误时机触发导致用户体验差。

完整代码示例 ​

ts
// 文件: examples/102-02-elform-schema-to-zod.ts（节选：Schema ↔ Zod 互转）
// 把 el-form 的 rules DSL 映射到 Zod schema，供前端/后端/测试共享
type ElRule = {
  required?: boolean;
  message?: string;
  trigger?: "blur" | "change";
  min?: number;
  max?: number;
  pattern?: RegExp;
  type?: "string" | "number" | "email" | "url";
};

type ElSchema = {
  [field: string]: ElRule[];
};

// Zod schema 的最小模拟（真实项目用 zod 包）
interface ZodSchema {
  parse(input: unknown): { ok: boolean; errors?: string[] };
}

function buildZod(schema: ElSchema): ZodSchema {
  const rules = schema;
  return {
    parse(input: unknown) {
      const errors: string[] = [];
      const data = input as Record<string, unknown>;
      for (const [field, fieldRules] of Object.entries(rules)) {
        const value = data?.[field];
        for (const rule of fieldRules) {
          if (rule.required && (value === undefined || value === null || value === "")) {
            errors.push(`${field}: ${rule.message ?? "必填"}`);
            continue;
          }
          if (typeof value !== "string" && rule.type !== "number") continue;
          const str = String(value ?? "");
          if (rule.min !== undefined && str.length < rule.min) {
            errors.push(`${field}: 至少 ${rule.min} 位`);
          }
          if (rule.max !== undefined && str.length > rule.max) {
            errors.push(`${field}: 最多 ${rule.max} 位`);
          }
          if (rule.pattern && !rule.pattern.test(str)) {
            errors.push(`${field}: ${rule.message ?? "格式错误"}`);
          }
          if (rule.type === "email" && str && !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(str)) {
            errors.push(`${field}: 邮箱格式错误`);
          }
        }
      }
      return { ok: errors.length === 0, errors };
    },
  };
}

// 同一套 schema，el-form rules 和 Zod 共用
const userSchema: ElSchema = {
  username: [
    { required: true, message: "请输入用户名", trigger: "blur" },
    { min: 3, max: 20, message: "3-20 位字符", trigger: "blur" },
    { pattern: /^[a-zA-Z0-9_]+$/, message: "只能含字母数字下划线", trigger: "blur" },
  ],
  email: [
    { required: true, trigger: "blur" },
    { type: "email", message: "邮箱格式不正确", trigger: "blur" },
  ],
};

const zod = buildZod(userSchema);
const pass = zod.parse({ username: "admin", email: "admin@test.com" });
const fail = zod.parse({ username: "a", email: "bad-email" });
assert.ok(pass.ok);
assert.ok(!fail.ok);
assert.equal(fail.errors!.length, 3); // 用户名短 + 邮箱 required + 邮箱格式

运行方式：npx tsx examples/102-02-elform-schema-to-zod.ts

应用实践 ​

  • el-form + Zod 双校验：前端提交前先跑 Zod（同步、快），el-form 规则负责 UI 交互体验，Zod 结果作为后端契约的共享校验逻辑
  • 动态表单用 computed 生成 rules：rules 写死在 options 里会导致条件显示字段的校验规则无法动态变化，用 computed(() => ({ ... })) 包裹
  • 重置表单别漏 resetFields：el-form.ref.resetFields() 只重置有 prop 属性的 el-form-item，动态新增的表单项如果没加 prop 会残留脏值

102.4 el-table 二次封装 ​

概念解析 ​

el-table 二次封装的核心价值是把重复的业务需求（分页、排序、虚拟滚动、列配置、空状态、加载状态、工具栏）封装成一个 <DataTable> 组件，调用方只传列配置和数据源。

列配置 DSL（DSL = Domain Specific Language）：把每一列的 prop / label / width / fixed / formatter / customRender 收敛成数组，el-table 通过 v-for 渲染：

ts
interface ColumnDef {
  prop?: string;
  label: string;
  width?: number | string;
  fixed?: "left" | "right";
  sortable?: boolean;
  formatter?: (row: any) => string;
  customRender?: (row: any) => unknown; // 传给具名插槽
}

虚拟滚动（衔接 第六十四部分 · 可编辑表格）：大数据量表格（>1000 行）启用 height + virtual-scroll prop，Element Plus 内置虚拟滚动支持；列配置 DSL 与虚拟滚动天然兼容——不要因为虚拟滚动重写列配置。

完整代码示例 ​

ts
// 文件: examples/102-03-eltable-column-dsl.ts（节选）
// 列配置 DSL → DataTable 的装饰器（分页 + 虚拟滚动 + 空状态自动注入）
import assert from "node:assert";

export interface ColumnDef {
  prop?: string;
  label: string;
  width?: number | string;
  fixed?: "left" | "right";
  sortable?: boolean;
  formatter?: (row: any) => string;
  slot?: string; // 具名插槽名，模板用 <template #slot="{ row }">
}

interface DataTableOptions {
  columns: ColumnDef[];
  data: any[];
  pageSize?: number;
  virtual?: boolean; // 自动触发虚拟滚动（>1000 行）
  emptyText?: string;
}

interface RenderPlan {
  // 给 el-table 的最终 prop（含装饰器自动填入的）
  tableProps: Record<string, unknown>;
  // 列定义数组（含装饰器计算后的）
  resolvedColumns: ColumnDef[];
  // 分页配置
  pagination?: { pageSize: number; total: number };
}

function resolveTable(opts: DataTableOptions): RenderPlan {
  // 自动触发虚拟滚动（>1000 行）
  const shouldVirtual = opts.virtual ?? opts.data.length > 1000;

  // 自动注入空状态（如果没传）
  const tableProps: Record<string, unknown> = {
    "data": opts.data,
    "empty-text": opts.emptyText ?? "暂无数据",
  };
  if (shouldVirtual) tableProps.height = 600; // 虚拟滚动必须设 height

  // 列配置：formatter → 插槽映射（Element Plus 推荐用具名插槽替代 formatter）
  const resolvedColumns = opts.columns.map((col, i) => ({
    ...col,
    slot: col.slot ?? col.prop ? `col-${col.prop}` : `col-${i}`,
    // 把 formatter 转成 slot（模板里 <template #col-prop="{ row }"> → formatter(row)）
    formatter: col.formatter,
  }));

  return {
    tableProps,
    resolvedColumns,
    pagination: { pageSize: opts.pageSize ?? 10, total: opts.data.length },
  };
}

// 验收：列配置 DSL 与装饰器的组合
const plan = resolveTable({
  columns: [
    { prop: "id", label: "ID", width: 80, sortable: true },
    { prop: "name", label: "名称", width: 160 },
    {
      prop: "status",
      label: "状态",
      width: 100,
      formatter: (r: any) => (r.active ? "启用" : "停用"),
    },
    { label: "操作", width: 180, fixed: "right" },
  ],
  data: Array.from({ length: 1500 }, (_, i) => ({ id: i, name: `item-${i}`, active: i % 2 === 0 })),
  pageSize: 20,
});

assert.equal(plan.resolvedColumns.length, 4);
assert.equal(plan.resolvedColumns[0].slot, "col-id", "formatter 列应自动生成具名插槽名");
assert.ok(plan.tableProps.height, "数据 > 1000 行时自动开启虚拟滚动");
assert.equal(plan.pagination?.pageSize, 20);
assert.equal(plan.pagination?.total, 1500);
console.log("[1] 列配置 DSL 装饰器：分页/虚拟滚动/插槽映射全部自动注入");

运行方式：npx tsx examples/102-03-eltable-column-dsl.ts

应用实践 ​

  • 列配置 DSL + 虚拟滚动：两者天然兼容，不要为了虚拟滚动重写列配置
  • formatter → 具名插槽：Element Plus 推荐把 formatter 改成具名插槽（更灵活、支持复杂交互），封装层可以自动做这个转换
  • 固定列 + 虚拟滚动：固定列（fixed: 'left' | 'right'）在虚拟滚动下会导致重复渲染，大数据量场景尽量不用固定列，或把固定列数据抽到行内

102.5 主题定制与暗黑模式 ​

概念解析 ​

Element Plus 主题系统基于 CSS 变量（Design Token）：--el-color-primary / --el-color-primary-light-3 等约 50 个核心 token，全部通过 CSS 变量暴露，主题定制的本质就是覆盖这些变量值。

暗黑模式的核心是切换 html 根节点的 class="dark"：

html
<!-- light -->
<html>

<!-- dark -->
<html class="dark">

Element Plus 会自动读取这个 class 来切换内置暗黑样式，不需要手动覆盖每个组件的颜色。

三种主题定制方式：

  1. CSS 变量覆盖（推荐，最灵活）：在全局 CSS 文件里覆盖变量值，支持运行时动态切换
  2. SCSS 变量覆盖（旧版 Element UI 方式）：$--el-color-primary: #ff6b6b，需要替换 SCSS 入口，不支持运行时切换
  3. Vite 插件动态换肤（vite-plugin-element-plus-theme）：构建期按主题名生成多份 CSS，运行时通过 <link> 切换

完整代码示例 ​

ts
// 文件: examples/102-04-theme-tokens.ts（节选）
// Design Token 提取 + CSS 变量注入策略（纯逻辑，不依赖运行时）
import assert from "node:assert";

// Element Plus 核心 Design Token（简化版，约 15 个高频 token）
interface ThemeTokens {
  primary: string; // 品牌主色
  "primary-light-3": string;
  "primary-light-5": string;
  "primary-light-7": string;
  "primary-light-9": string;
  "primary-dark-2": string;
  success: string;
  warning: string;
  danger: string;
  info: string;
  textPrimary: string;
  textRegular: string;
  textSecondary: string;
  borderColor: string;
  bgColor: string;
}

type PaletteName = "light" | "dark";

// 从主色派生 Element Plus 需要的 light-n / dark-2 色阶
function generatePalette(primary: string, mode: PaletteName): ThemeTokens {
  // 把 hex 转 hsl，按百分比调整亮度（light 提升亮度，dark 降低）
  function hexToHsl(hex: string): [number, number, number] {
    const h = hex.replace("#", "");
    const r = parseInt(h.slice(0, 2), 16) / 255;
    const g = parseInt(h.slice(2, 4), 16) / 255;
    const b = parseInt(h.slice(4, 6), 16) / 255;
    const max = Math.max(r, g, b), min = Math.min(r, g, b);
    let hh = 0;
    if (max !== min) {
      const d = max - min;
      hh = (max === r ? (g - b) / d : max === g ? (b - r) / d : (r - g) / d) + (g < r ? 6 : 0);
      hh *= 60;
    }
    const l = (max + min) / 2;
    const s = max === min ? 0 : l > 0.5 ? (max - min) / (2 - max - min) : (max - min) / (max + min);
    return [hh, s, l];
  }

  function hslToHex(h: number, s: number, l: number): string {
    const c = (1 - Math.abs(2 * l - 1)) * s;
    const x = c * (1 - Math.abs(((h / 60) % 2) - 1));
    const m = l - c / 2;
    const [r, g, b] =
      h < 60 ? [c, x, 0]
      : h < 120 ? [x, c, 0]
      : h < 180 ? [0, c, x]
      : h < 240 ? [0, x, c]
      : h < 300 ? [x, 0, c]
      : [c, 0, x];
    const toHex = (v: number) => Math.round((v + m) * 255).toString(16).padStart(2, "0");
    return `#${toHex(r)}${toHex(g)}${toHex(b)}`;
  }

  const [h, s, l] = hexToHsl(primary);
  const lighten = (pct: number) => hslToHex(h, s, Math.min(1, l + pct));
  const darken = (pct: number) => hslToHex(h, s, Math.max(0, l - pct));

  if (mode === "light") {
    return {
      primary,
      "primary-light-3": lighten(0.3),
      "primary-light-5": lighten(0.5),
      "primary-light-7": lighten(0.7),
      "primary-light-9": lighten(0.9),
      "primary-dark-2": darken(0.1),
      success: "#67c23a", warning: "#e6a23c", danger: "#f56c6c", info: "#909399",
      textPrimary: "#303133", textRegular: "#606266", textSecondary: "#909399",
      borderColor: "#dcdfe6", bgColor: "#ffffff",
    };
  }
  // dark 模式：整体反色，primary 稍亮
  return {
    primary: lighten(0.1),
    "primary-light-3": lighten(0.4),
    "primary-light-5": lighten(0.6),
    "primary-light-7": lighten(0.8),
    "primary-light-9": lighten(0.95),
    "primary-dark-2": darken(0.05),
    success: "#85ce61", warning: "#ebb563", danger: "#f78989", info: "#a6a9ad",
    textPrimary: "#e5eaf3", textRegular: "#cfd3dc", textSecondary: "#a3a6ad",
    borderColor: "#414243", bgColor: "#141414",
  };
}

function injectThemeVars(root: HTMLElement, tokens: ThemeTokens) {
  const style = root.style;
  for (const [k, v] of Object.entries(tokens)) {
    style.setProperty(`--el-${k.replace(/([A-Z])/g, "-$1").toLowerCase()}`, v);
  }
}

// 验收：主色派生 + 暗黑模式反色
const light = generatePalette("#409EFF", "light");
const dark = generatePalette("#409EFF", "dark");
assert.equal(light.primary, "#409EFF");
assert.ok(light.bgColor === "#ffffff" && dark.bgColor === "#141414");
assert.ok(dark.primary !== light.primary, "暗黑模式主色应稍亮以保持可见性");
assert.ok(dark.textPrimary === "#e5eaf3" && dark.bgColor === "#141414");
console.log("[1] Design Token 派生：light/dark 双模式全部色阶自动生成");
console.log("[2] CSS 变量注入：injectThemeVars 一次覆盖全部 15 个核心 token");

运行方式：npx tsx examples/102-04-theme-tokens.ts

应用实践 ​

  • 暗黑模式 = html.dark class 切换 + CSS 变量覆盖：Element Plus 内置支持，不要手动给每个组件写两套 class
  • 主题色只改 --el-color-primary 一个变量：--el-color-primary-light-3/5/7/9 和 --el-color-primary-dark-2 会自动从主色派生（Element Plus 在运行时做了 HSL 计算），但为了打包确定性，建议在 CSS 文件里显式覆盖这 6 个色阶
  • 不要用 SCSS 变量覆盖（旧版方式）：$--el-color-primary: #ff6b6b 需要替换 SCSS 入口，不支持运行时切换。CSS 变量方式随时可用 JS 修改 document.documentElement.style.setProperty('--el-color-primary', newColor)

102.6 Vant 移动端适配 ​

概念解析 ​

Vant 是移动端 H5 的首选框架，与 Element Plus 的核心差异在于适配策略——移动端需要处理视口单位、安全区、状态栏高度、物理分辨率缩放等问题。

rem/vw 双方案：

方案原理适用场景
rem + amfe-flexible动态修改 html 的 font-size（iPhone 6 设 37.5px），组件尺寸用 rem经典方案，兼容性好
postcss-px-to-viewport构建时把 px 自动转换成 vw/vh新项目首选，更现代

安全区适配：iPhone 刘海屏/底部安全区需要额外 padding，Vant 内置了 --safe-area-inset-top/bottom 变量：

css
body {
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
}

应用实践 ​

  • 新项目直接用 postcss-px-to-viewport，在 postcss.config.js 里配置 viewportWidth: 375，设计稿按 375 宽度标注，开发者写 px，构建自动转 vw
  • Vant 组件的字体默认 px，启用 postcss-px-to-viewport 后自动转 vw，不需要额外配置 Vant
  • 真机调试：iPhone 刘海屏浏览器用 env()，微信小程序用 wx.getSystemInfoSync().safeArea

102.8 自测题 ​

1. Element Plus 的按需自动导入需要哪两个 Vite 插件？它们各自解决什么问题？【基础】

需要 unplugin-auto-import/vite 和 unplugin-vue-components/vite，共用 ElementPlusResolver。前者自动识别并导入组合式 API（如 ElMessage、ElNotification、ElMessageBox），后者自动识别模板中的 <el-button> <el-form> <el-table> 等标签并注册对应组件。两者配合才能同时解决"脚本里的 API 不用手动 import"和"模板里的组件不用手动注册"两个问题。

2. el-form 的 rules 支持哪三种校验规则来源？各自的典型用法是什么？【基础】

三种来源：① el-form 内置规则（required: true、pattern: /regex/、type: 'email' 等简单校验字段）；② 自定义校验函数（validator: (rule, value, callback) => { ... }，适合异步校验、跨字段联动、复杂业务逻辑）；③ 外部 schema 库（Zod / Yup / async-validator 与 el-form rules 互转，把校验逻辑作为前后端共享的单一数据源，参见 33 册 Schema 与类型校验）。实战中推荐：前端表单体验用 el-form 规则，数据契约一致性用 Zod 等 schema 库共享。

3. Element Plus 主题定制的核心机制是什么？暗黑模式如何实现？【进阶】

核心是 CSS 变量（Design Token）：Element Plus 暴露了约 50 个 CSS 变量（--el-color-primary、--el-color-primary-light-3、--el-color-primary-dark-2 等），主题定制就是在全局 CSS 里覆盖这些变量值，支持运行时动态切换。暗黑模式的实现是切换 html 根节点的 class="dark"，Element Plus 会自动读取这个 class 来切换内置暗黑样式，不需要手动覆盖每个组件的颜色。注意：不要用旧版 SCSS 变量覆盖方式（需要替换 SCSS 入口、不支持运行时切换），CSS 变量方式可随时用 JS 修改。

4. 从 Element UI 升级到 Element Plus 有哪些 Breaking Changes？至少说出 5 条。【进阶】

① 全局 API 调用方式变了：this.$message / this.$notify → ElMessage / ElNotification（组合式 API，不再挂在 prototype 上）；② .sync 修饰符移除，所有 .sync 改成 v-model；③ .native 修饰符移除（Vue 3 自动识别原生事件）；④ 过滤器管道 {{ x | y }} 整体移除，改成计算属性或方法调用；⑤ 生命周期改名：beforeDestroy / destroyed → onBeforeUnmount / onUnmounted；⑥ 插槽语法从 slot="xxx" 改成 <template #xxx>；⑦ 按需导入方案从 babel-plugin-component（Babel 时代）换到 unplugin-auto-import + unplugin-vue-components（Vite 时代）。

5. el-table 大数据量场景如何优化？列配置 DSL 与虚拟滚动如何配合？【进阶】

大数据量优化的核心是虚拟滚动：Element Plus 内置支持 height prop（虚拟滚动必须设 height）+ 虚拟滚动能力，只渲染可见行的 DOM。列配置 DSL（ColumnDef 数组）与虚拟滚动天然兼容——resolvedColumns 传递给 el-table 的 :columns 或 v-for 渲染，虚拟滚动只关心行数据长度和行高，与列配置无关。注意：固定列（fixed: 'left' | 'right'）在虚拟滚动下会导致重复渲染，大数据量场景尽量不用固定列，或把固定列数据抽到行内显示。

6. 一个 30 页的 Vue 2 + Element UI 项目要升级到 Vue 3 + Element Plus，请给出迁移方案（路线、批次、风险控制）。【挑战】

路线选 Vue Compat 渐进式（不能停业务），分五批：① 基建批（Vue 2.7 过渡 + vue-router 4 + vuex 4 + vite + unplugin 按需导入框架搭建 + @vue/compat alias）；② 机械替换批（全局 API→app.use、.sync→v-model、.native→移除、生命周期改名、过滤器→计算属性、.native→移除，专项 PR）；③ Element Plus 专项批（Element UI 卸载、Element Plus 安装、全局 API 替换 this.$message→ElMessage、按需导入配置、样式入口替换、视觉回归逐页对比）；④ 二次封装升级批（el-form / el-table / el-dialog 等高频封装升级、主题 CSS 变量覆盖、暗黑模式 class 切换）；⑤ 去兼容层批（移除 @vue/compat alias、compatConfig: { MODE: 3 }、灰度监控回归、清理 lint 豁免）。风险控制：每批一个专项 PR + 核心链路 E2E 回放 + 错误监控分桶对照 + 配置中心保留回滚开关；CI 加防回退门禁（禁止新增 Vue 2 专属写法）。
