第一百二十一部分 · UniApp 与 Electron 深度实战 ​

🧭 返回总目录｜上一篇：第一百二十部分 · 活动搭建与投放闭环｜关联章节：第八十八部分 · UniApp 跨端开发 · 第九十一部分 · Electron 桌面开发深化 · 第七十部分 · 桌面应用开发 Tauri · 第一百一十三部分 · Vue 3 单仓多端工程 · 第七十三部分 · 多端共用架构 · 第五十六部分 · 离线与本地缓存全景

本部分内容 ​

这一册把 UniApp 与 Electron 合到一起，解决「一套代码覆盖小程序、H5、App 与桌面端」。四条边界：条件编译只出现在适配层、平台能力有契约与降级链、IPC 白名单 + 参数校验、更新签名可验且可回滚。四个示例覆盖编译产物、四端适配、IPC 闸门与更新状态机。

121.1 UniApp 架构与条件编译深化 ​

概念解析 ​

UniApp 的「一套代码」是编译期复用：同一份 SFC 生成 H5 的 DOM 页面、小程序的双线程包、App 的 WebView/nvue 页面。条件编译在 JS 解析前执行，// #ifdef 块在非目标端产物中根本不存在，同时解决包体、API 缺失崩溃与实现泄漏。运行时 if 两端代码都会进包——判断标准是「这段代码在错误平台是否允许存在」。

平台标识产物典型差异
H5WebDOM、Web Share、浏览器路由
MP-WEIXIN / MP-ALIPAY小程序无 DOM、包体限额、平台支付
APP-PLUS / APP-HARMONYAppplus 能力；Harmony 为能力子集

三条硬规则：指令独占一行且只认注释；多端合并用 ||；#ifndef 是显式兜底，不是补丁。

完整代码示例 ​

ts
// 文件: examples/121-01-conditional-compile.ts（节选）
// 平台矩阵是唯一事实源；缺实现直接失败，产物由 compileFor() 剥离
const blocks = MATRIX[capability];
const missing = targets.filter((t) => !new Set(blocks.flatMap((b) => b.platforms)).has(t));
if (missing.length > 0 && !fallback) throw new Error(`E_MISSING_IMPL: ${missing.join(', ')}`);
const lines = blocks.flatMap((block) => {
    const hit = block.platforms.filter((p) => targets.includes(p));
    return hit.length > 0 ? [`// #ifdef ${hit.join(' || ')}`, block.code, '// #endif'] : [];
});
return lines.join('\n');

运行方式：npx tsx examples/121-01-conditional-compile.ts

断言：5 端合并为 4 块；微信产物不含 navigator；Harmony 落入兜底；缺实现与未知平台直接失败；未闭合指令被拒绝。

应用实践 ​

海外社交电商同时发小程序、H5、App，分享覆盖详情、邀请、直播预约。矩阵是唯一事实源，CI 对产物双向断言：H5 不得有 wx.，小程序不得有 navigator。反例：只写 H5 的 navigator.share 且无 #ifndef，App 点击抛 ReferenceError，按钮永远无响应。

最佳实践 ​

  • ✅ 平台专属 import 放进 #ifdef 内，避免另一端被打包。
  • ✅ 新增平台先补矩阵与 fallback，再写实现。

121.2 平台 API 抽象与原生能力 ​

概念解析 ​

「用 uni.xxx 不等于抽象好了」：它抹平函数名，没抹平语义与可用性。分享在小程序是转发卡片、H5 是 Web Share 或复制、App 是系统面板、桌面是打开浏览器；支付、配额、文件系统各不相同。业务直调 API，等于把平台差异写进业务规则。

正确模型是契约 + 适配器 + 降级链：契约只描述业务语义，不出现平台名；适配器注入运行时能力；降级按「原生 → 系统 → 通用」排序并返回可识别结果；能力探测优先于 UA。

能力小程序H5AppElectron
分享转发卡片Web Share / 复制系统面板外部浏览器
存储约 10KB/keyIndexedDBplus 持久化用户目录文件
支付平台支付跳收银台支付 SDK不承载，转 H5

完整代码示例 ​

ts
// 文件: examples/121-02-platform-adapter.ts（节选）
// 降级链：原生 → 系统浏览器 → 复制，每一级都返回结果
if (env.nativeShare?.(payload).ok) return { channel: 'native', ok: true, degraded: false };
if (kind === 'electron' && env.openExternal?.(payload.url)) return { channel: 'external', ok: true, degraded: false };
env.clipboardWrite(`${payload.title} ${payload.url}`);
return { channel: 'copy', ok: true, degraded: true }; // 降级必须可见

BoundedStorage.set() 先算 UTF-8 字节数，超限返回 false 且不覆盖旧值；桌面端 pay() 抛 E_PAYMENT_UNSUPPORTED。

运行方式：npx tsx examples/121-02-platform-adapter.ts

应用实践 ​

商品详情页在四个容器跑：小程序分享给好友、H5 复制链接、App 唤起系统分享、Electron 打开浏览器。业务只调 capabilities.share()；原生失败自动复制并提示，同时把 degraded 打进埋点。

最佳实践 ​

  • ✅ 适配器工厂接收注入的 env，单测不依赖真机与真 SDK。
  • ✅ 降级不是静默：返回 degraded/错误码，UI 与埋点都要消费。

121.3 分包、性能与上架 ​

概念解析 ​

体积在编译期定型。分包不是「挪目录」，而是按用户到达路径切分下载：主包只放启动必需，低频业务进分包，活动页做独立分包，再用 preloadRule 预下载高转化下一步。

容器限额/预算超标后果正确动作
微信主包2MB上传失败只留启动链路
微信单分包2MB上传失败按页面再拆
微信总计20MB上传失败静态资源上 CDN
H5 首屏 JS建议 < 200KB gzip首屏变慢路由级动态 import

上架材料是发布物的一部分：小程序过类目与隐私审核；App 处理权限声明、隐私清单、加密出口、账号删除入口；海外商店的数字商品必须走平台内购。

代码与配置 ​

json
// pages.json：按业务域分包，详情页预下载结算分包
{
    "pages": [{ "path": "pages/index/index" }],
    "subPackages": [{ "root": "pkg-catalog", "pages": [{ "path": "detail/index" }] }, { "root": "pkg-checkout", "pages": [{ "path": "cart/index" }] }],
    "preloadRule": { "pkg-catalog/detail/index": { "network": "all", "packages": ["pkg-checkout"] } }
}

预下载只配「下一步大概率去哪」；全配等于把分包重新合成一个大包。

应用实践 ​

海外大促：主包只留首页、登录、WebView 与错误页；列表/详情进 pkg-catalog，购物车/支付进 pkg-checkout。详情页预下载结算分包后，首屏到加购从 1.8s 降到 0.9s。反例：所有页面塞主包，2.3MB 上传被拒，再靠删注释抠 KB——应拆低频业务。

最佳实践 ​

  • ✅ 主包预算进 CI 门禁，超限失败并输出体积报告。
  • ✅ 分包按用户路径切，不按代码目录切。

121.4 Electron 进程模型与 IPC 安全 ​

概念解析 ​

安全模型只有一句话：渲染进程不可信。它加载远程内容、执行第三方脚本，不能直接拿 Node 能力。主进程持有文件、网络、Shell；preload 是唯一闸门，用 contextBridge 暴露最小 API。

配置正确值错误后果
nodeIntegrationfalse页面可 require('child_process')
contextIsolationtrue页面可篡改 preload 对象
sandboxtruepreload 获得过多 Node 能力
webSecurity / setWindowOpenHandlertrue / 默认 deny跨站读取、任意协议被打开

关键不是「有没有校验」，而是校验在哪一层。preload 通用透传 invoke(channel, ...args) 等于把主进程全部频道暴露给页面：只要注册过 fs:writeFile、shell:openExternal，XSS 就能逐条试出来。正确做法是一能力一具名方法 + 注册表 + 参数 schema + 按窗口授权。

完整代码示例 ​

ts
// 文件: examples/121-03-ipc-whitelist.ts（节选）
// 唯一入口：白名单 → 角色 → 参数 → handler
const definition = registry.get(channel);
if (!definition) return { ok: false, code: 'E_CHANNEL_NOT_ALLOWED', message: '通道不存在或未授权' };
if (ROLE_WEIGHT[caller.role] < ROLE_WEIGHT[definition.minRole]) return { ok: false, code: 'E_PERMISSION_DENIED', message: '权限不足' };
const validation = definition.validate(payload);
if (!validation.ok) return { ok: false, code: validation.code, message: validation.message };
return { ok: true, data: definition.handle(validation.value, caller) };

file:read 仅允许 /data/docs/ 下且禁止 ..；shell:openExternal 必须 https: 且命中域名白名单；system:exec 从未注册，管理员也调不到；被拒调用不增加 handler 计数。

运行方式：npx tsx examples/121-03-ipc-whitelist.ts

应用实践 ​

真实事故：卖家营运台内嵌第三方客服网页，开 nodeIntegration: true，preload 又暴露通用 invoke。网页被供应链脚本注入后遍历频道名，调用文件写入与 Shell，把恶意程序写进启动项——XSS 升级为 RCE。修复：关 Node、开沙箱、删透传、按窗口发角色、双白名单。

最佳实践 ​

  • ✅ preload 只暴露具名方法，永不暴露 ipcRenderer 本身。
  • ✅ 频道常量由共享包导出，主进程注册表是唯一真相。
  • ✅ 参数校验放主进程，不能只信 TypeScript 类型。

121.5 自动更新与签名 ​

概念解析 ​

自动更新是一条信任链：HTTPS 服务器 → 清单（版本、哈希、签名）→ 下载器校验 → 安装器验签。只靠 HTTPS 不够：macOS 要 Developer ID 签名 + Hardened Runtime + 公证并 staple；Windows 要 Authenticode，否则被 SmartScreen 拦截；electron-updater 还校验 sha512 与发布者名。

状态进入条件允许禁止
idle初始/无更新checkdownload
available发现更高版本downloadinstall
downloading / ready下载中 / 哈希通过进度 / install安装 / 继续下载
error网络/校验失败retryinstall

失败必须回滚：清半成品引用、进度归零、保留错误码。停在 ready 会让用户安装半包；保留 .part 续传而不重验哈希，坏包会被当成品。

完整代码示例 ​

ts
// 文件: examples/121-04-update-state.ts（节选）
// 下载成功且哈希一致才 ready；任何失败先回滚
this.state = 'downloading';
const artifact = await this.downloader.download(this.release!);
if (artifact.sha256 !== this.release!.sha256) { this.rollback('E_CHECKSUM'); throw new Error('E_CHECKSUM'); }
this.stagedPath = artifact.path;
this.state = 'ready';
// rollback(): stagedPath=null、progress=0、state='error'

rollback() 置 stagedPath = null、progress = 0、state = 'error'；retry() 只把 error 退回 available。

运行方式：npx tsx examples/121-04-update-state.ts

应用实践 ​

海外营运台灰度：清单带 channel 与 rollout: 5%，按安装 id 分桶，观察 24 小时崩溃率与更新成功率再放量；校验失败单独上报 E_CHECKSUM，通常意味着 CDN 污染。反例：http:// 且不验签，中间人可替换安装包；或失败仍把 .part 写进 ready，安装器报损坏。

最佳实践 ​

  • ✅ 清单与安装包都走 HTTPS，哈希与平台签名双校验。
  • ✅ 版本号单调递增，拒绝降级清单，防回滚攻击。
  • ✅ 失败回滚到 error 再重试，绝不进入 ready。

121.6 系统能力与离线 ​

概念解析 ​

托盘、通知、全局快捷键、开机自启、自定义协议、文件对话框、休眠抑制都在主进程/原生层，必须经过权限与用户可见开关；默认开启快捷键、静默写启动项会被视为流氓行为。

离线分三层：读缓存（先渲染快照再回源）、写队列（outbox 按序重放，带幂等键）、冲突解决（版本号乐观锁，冲突保留双方而非后写覆盖）。

能力UniApp App小程序Electron
本地数据库plus.sqlite平台 storageSQLite（主进程）
系统通知plus.push订阅消息Notification
自定义协议Scheme受限setAsDefaultProtocolClient

离线不是「塞进 localStorage」：Electron 更新/清分区可能让它消失，小程序 storage 有单 key 限制，H5 隐私模式可能禁用 IndexedDB——存储同样需要契约与降级。

代码与结构 ​

ts
// 离线写队列：幂等键 + 版本基线 + 重试元数据
interface OutboxRecord {
    id: string;            // 客户端生成，服务端按它去重
    entity: 'cart' | 'address' | 'review';
    op: 'upsert' | 'delete';
    payload: unknown;
    baseVersion: number;   // 乐观锁基线
    attempts: number;
    nextRetryAt: number;
}

重放用指数退避 + 最大次数；baseVersion 落后时进冲突队列，不直接覆盖；成功后按 id 删除，失败保留供人工恢复。

应用实践 ​

海外卖家营运台常在仓库/展会弱网使用：草稿、库存、订单备注先写 SQLite，UI 立即成功；联网后按 id 幂等重放，冲突提示「已被其他设备修改」。反例：只改内存数组、联网逐条 POST 且无幂等键——重试生成两笔订单，后写静默覆盖。

最佳实践 ​

  • ✅ 读缓存带 TTL 与「可能过期」提示，不把缓存当真相。
  • ✅ 写队列必须有幂等键、版本基线、重试上限与死信队列。

121.7 双端共用代码策略 ​

概念解析 ​

目标是业务内核复用，表现层与能力层分离，不是追求 100% 复用率。可共享代码有硬门槛：纯 TypeScript、不访问平台全局、依赖参数注入、无 UI 框架耦合。满足四条，定价、优惠、购物车、订单状态机才能同时跑在 UniApp 与 Electron。

层内容合理复用率说明
core定价、税费、优惠、订单状态机90%+纯函数，逐字节共享
contracts能力接口、频道常量、错误码100%只有类型与常量
adapters分享、存储、支付、文件≈0%端端不同是设计目的
ui页面与业务组件20%~50%交互范式不同，允许分叉
app-shell生命周期、路由、构建配置≈0%平台入口

三道保险：依赖方向检查（core 不得 import adapters/ui）、契约测试（同一组用例跑四端）、构建矩阵校验（每端产物过体积与标记断言）。共享包按语义版本发布，存储 schema 变更必须带迁移函数。

代码与分层 ​

ts
// 共享领域层：不 import 任何平台 API，能力通过参数注入
interface Clock { now(): number; }

function quoteCart(lines: CartLine[], rules: PriceRule[], clock: Clock): Quote {
    const subtotal = lines.reduce((sum, line) => sum + line.unitMinor * line.qty, 0);
    const discount = rules.reduce((sum, rule) => sum + Math.round(subtotal * rule.rate), 0);
    return { subtotal, discount, total: subtotal - discount, quotedAt: clock.now() };
}

UniApp 商品页与 Electron 报价面板都调 quoteCart，时钟与汇率由适配器注入——改一次价格规则两端同时生效。

应用实践 ​

某海外社交电商把「邀请返利 + 购物车 + 优惠叠加」放共享 core：移动三端下单，Electron 营运台改价查单，业务代码复用 82%，避免「两端算出不同总价」。反例：ProductList.vue 同时 import 小程序组件与桌面表格，包体涨 40%、样式互相覆盖。

最佳实践 ​

  • ✅ 共享模型与规则，不共享页面；UI 低复用不是失败。
  • ✅ core 禁止平台全局与副作用，时间/随机/存储全部注入。
  • ✅ 存储 schema 带版本与迁移，升级不丢用户数据。

121.8 自测题 ​

先自己作答，再展开参考答案。

1. 条件编译和运行时 if 的本质区别？【基础】

条件编译在解析前执行，非目标端产物中代码完全不存在；运行时判断两端都进包。错误平台绝不能存在的代码用前者，正常分支用后者。

2. 多端分享返回值为什么带 degraded？【基础】

它标记本次成功走了复制等兜底路径，UI 可提示，埋点能统计原生失败率；只返回 ok: true 会让运营误判。

3. 小程序主包、分包、总计限额怎么配 preloadRule？【进阶】

微信主包 2MB、单分包 2MB、总计 20MB（以平台规则为准）。主包只放启动必需，按用户路径拆分包；preloadRule 只配下一步大概率进入的分包。

4. Electron 的安全基线有哪几条？【基础】

nodeIntegration: false、contextIsolation: true、sandbox: true、webSecurity: true；再加严格 CSP 与 setWindowOpenHandler 默认拒绝。

5. 通用 invoke(channel, ...args) 如何把 XSS 升级成 RCE？【挑战】

它暴露主进程全部频道，攻击者可遍历 fs:write、shell:openExternal、child_process:exec 写文件、执行命令。应一能力一具名方法 + 角色/schema/白名单。

6. macOS 与 Windows 更新包各需哪些签名环节？【进阶】

macOS：Developer ID → Hardened Runtime → 公证 → staple。Windows：Authenticode；electron-updater 再校验发布者与哈希。

7. 更新下载失败为什么必须回滚？【进阶】

ready 表示已有完整且校验通过的包；失败仍停留会让用户安装坏包。回滚清半成品、进度归零、记错误码、回 error，再 retry。

8. 离线写队列为什么需要幂等键与版本基线？【挑战】

重复点击、自动重试、队列重放都会重复提交；无幂等键会重复下单扣库存。幂等键客户端生成且重试不变；baseVersion 乐观锁冲突时进冲突队列。

121.9 本章避坑清单 ​

#坑点现象根因正确姿势
1只写正向 #ifdef新平台点击无响应未覆盖端无实现也无兜底每能力必须有 fallback
2条件编译写进业务组件同一规则多份分支平台差异泄漏到领域层差异收敛到 adapters/
3业务直调 wx.* / navigator.*H5 或小程序崩在回调没有契约与能力探测统一适配器 + 降级
4存储超限静默截断用户数据丢一半写入前没算配额超限返回失败并保留旧值
5分享降级不告知用户以为分享成功丢弃 degraded返回标记，UI 提示并埋点
6nodeIntegration: true页面可执行任意命令渲染进程被当成可信关 Node、开隔离与沙箱
7preload 通用 invoke 透传XSS 可枚举全部频道没有具名方法与白名单一能力一方法 + 注册表
8只信 TypeScript 类型越权路径/任意 URL 放行类型运行时不存在主进程 schema + 白名单
9更新源 HTTP 且不验签安装包被替换信任链断在传输与安装HTTPS + 哈希 + 签名/公证
10下载失败仍进 ready安装坏包后应用起不来状态语义错误、未回滚清半成品、回 error

心法：跨端的难点不是「写一套代码」，而是守住四条边界——编译期只剥离该剥离的、能力层只暴露该暴露的、IPC 只放行该放行的、更新只安装该安装的。边界清楚，一套代码才是资产。
