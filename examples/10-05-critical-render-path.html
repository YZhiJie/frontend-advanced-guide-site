实验 2：预加载扫描器（preload scanner）

解析器被阻塞脚本卡住时，浏览器会派出"预加载扫描器"向后扫，提前发现 <img>、<link>、<script> 等外链资源并行预取，不必等解析器走到那里才发起请求。

在任意真实页面的 DevTools 中验证：打开 Network 面板刷新，会看到靠后的 <img> 请求在文档加载早期就已发出（与 head 里的阻塞脚本并行）；关键资源（LCP 图片、首屏字体）还可以用 <link rel="preload" as="image"> 与 fetchpriority="high" 主动插队。（本实验不内嵌外部图片，保证离线打开也无 404 噪音。）

实验 4：CSS 阻塞渲染（Performance 面板观察法）

  1. DevTools → Performance → 勾选 Screenshots，刷新页面；
  2. 首帧（FCP）之前可以看到 Parse HTML 与 Recalculate Style（CSSOM 构建）两条轨道；
  3. 把一个慢样式表放到 head（如 @import 串行加载），会发现 CSSOM 未就绪前浏览器不绘制任何内容（白屏）——CSS 不阻塞 DOM 解析，但阻塞渲染；
  4. 对策：关键 CSS 内联进 <style>、非关键 CSS 用媒体查询拆分或 media="print" 降级、避免 @import 串行。
