第一百三十三部分 · 浏览器内数据库——SQLite WASM、PGlite 与 DuckDB WASM ​

IndexedDB 解决的是「按 key 存结构化对象」，解决不了「多表关联、聚合、窗口函数、复杂条件查询」。当业务把越来越多的计算推到本地——离线报表、本地搜索、数据导入预览、端侧分析——就需要真正的数据库引擎。本册讲清三种主流方案的边界与落地：SQLite WASM 做事务型本地库，PGlite 复用 PostgreSQL 生态，DuckDB WASM 做列式分析。

前置阅读：132 浏览器存储工程手册（介质选型、配额、迁移）、19.9 IndexedDB 结构化仓储（IDB 基础与游标分页）、17.4 WebAssembly 适用边界（WASM 加载管线）、18 Worker 家族（线程模型）、56 离线缓存（离线队列）。

技术基线（2025-11）：@sqlite.org/sqlite-wasm 3.49.x、@electric-sql/pglite 0.3.x、@duckdb/duckdb-wasm 1.29.x + apache-arrow 17.x。三个包都是浏览器 WASM 运行时，本册示例全部走 StackBlitz 在线运行（正文保留单源核心片段，不在 Node 里 npx tsx 实跑）；纯逻辑的迁移与基准仍以 TS 写，便于对照改造。

读法：133.1 做选型；133.2–133.4 分别是三个引擎的最小可用路径；133.5–133.7 是上线前必须处理的迁移、Worker 与体积问题；133.8 是落地清单。

133.1 选型：什么时候值得把数据库搬进浏览器 ​

先明确一件事：浏览器内数据库不是「更先进的 localStorage」。它带来 SQL 能力的同时，也带来数 MB 的 WASM 下载、首屏初始化、单写者锁与版本升级成本。只有当「本地查询复杂度」高到用 IDB 手写索引与聚合不划算时，才值得引入。

三种引擎的定位 ​

引擎内核强项弱项典型场景
SQLite WASMSQLite 3事务、索引、单文件、生态成熟单写者；复杂分析弱于列式离线 CRUD、本地草稿、端侧业务库
PGlitePostgreSQL 16（WASM 编译）复用 PG 语法/类型/扩展、jsonb、窗口函数包体更大，初始化更慢已有 PG 后端，想本地复用 SQL 与 schema
DuckDB WASMDuckDB（列式）Parquet/CSV 直查、聚合快、Arrow 零拷贝不适合高频小事务写入本地报表、数据预览、端侧分析

决策路径 ​

mermaid
flowchart TD
    A[需要本地持久化 + 查询] --> B{需要 SQL / 多表 / 聚合?}
    B -- 否 --> C[IndexedDB / OPFS 足够<br/>见 132 册]
    B -- 是 --> D{数据形态?}
    D -- 高频小事务、离线 CRUD --> E[SQLite WASM<br/>或 PGlite]
    D -- 大文件 / Parquet / 报表聚合 --> F[DuckDB WASM]

    E --> H{是否已有 PG 生态?}
    H -- 是 --> G
    H -- 否 --> E

三条硬约束（先确认再动手） ​

  1. 体积：SQLite WASM 约 1MB 级，PGlite 首次加载数 MB，DuckDB 视 bundle 而定。必须动态 import()，不要进首屏主包。
  2. 线程：需要多线程时依赖 SharedArrayBuffer，页面要发 Cross-Origin-Opener-Policy: same-origin 与 Cross-Origin-Embedder-Policy: require-corp；否则只能单线程跑。
  3. 持久化：三家都能落 IndexedDB 或 OPFS，但同一时刻只应有一个标签页持有写连接；跨标签页并发写没有服务端锁兜底。

133.2 SQLite WASM：OPFS 持久化与 SAH Pool ​

SQLite WASM 官方包提供三种运行形态：内存库、OPFS 普通 VFS、OPFS SAH Pool VFS。生产里优先 SAH Pool：它把 OPFS 的同步访问句柄池化，绕开主线程只能异步写的限制，性能接近原生文件。

最小可用路径 ​

typescript
// 文件: examples/133-01-sqlite-opfs.ts
import { sqlite3InitModule } from "@sqlite.org/sqlite-wasm";

const sqlite3 = await sqlite3InitModule({
    print: (msg) => console.log("[sqlite]", msg),
    printErr: (msg) => console.error("[sqlite:err]", msg),
});

// OPFS 上的连接池 VFS：database 文件落在源私有文件系统里，刷新页面仍在
const pool = await sqlite3.installOpfsSAHPoolVfs({ name: "fag-sqlite-pool" });
const db = new pool.OpfsSAHPoolDb("/fag.sqlite3");

db.exec(`
  CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    body TEXT NOT NULL,
    updated_at INTEGER NOT NULL
  );
  CREATE INDEX IF NOT EXISTS idx_notes_updated ON notes(updated_at DESC);
`);

预编译语句是写入性能的分水岭 ​

typescript
// [项目内运行] 同一结构循环写入时，prepare 一次、bind 多次
const insert = db.prepare("INSERT INTO notes (title, body, updated_at) VALUES (?, ?, ?)");
try {
    for (const note of notes) {
        insert.bind([note.title, note.body, Date.now()]).stepReset();
    }
} finally {
    insert.finalize(); // 不 finalize 会一直占着语句句柄
}

db.exec() 适合建表与一次性脚本；批量写入必须用 prepare + stepReset，否则每条 SQL 都重新解析。写入包一层事务，速度差异通常是数量级的：

typescript
db.exec("BEGIN");
try {
    // ... 批量 bind
    db.exec("COMMIT");
} catch (error) {
    db.exec("ROLLBACK");
    throw error;
}

VFS 怎么选 ​

VFS持久化适用注意
默认内存否单元测试、临时计算刷新即失
opfs是单连接、少量文件主线程写入受限
opfs-sahpool是生产首选同一时刻单写者；容量按池配置

边界 ​

  • OPFS 需要 secure context（localhost 或 HTTPS），file:// 直接打开会失败；
  • 同一时刻只有一个标签页能持有 SAH pool 的写锁，多标签页要配合 navigator.locks 或 BroadcastChannel 让出写权；
  • 用户「清除站点数据」会连库一起删，关键数据仍要同步服务端；
  • SQLite 的 AUTOINCREMENT 与 INTEGER PRIMARY KEY 语义不同，前者保证单调不复用，后者更省空间。

133.3 PGlite：把 PostgreSQL 跑在浏览器里 ​

PGlite 把 PostgreSQL 编译成 WASM，最大的价值不是「浏览器里也能跑 SQL」，而是本地 schema、SQL、类型系统与后端完全一致。已有 PG 后端的团队，可以把同一份 DDL 与查询直接复用到前端离线库。

持久化与最小查询 ​

typescript
// 文件: examples/133-02-pglite-query.ts
import { PGlite } from "@electric-sql/pglite";

// idb:// 前缀表示落 IndexedDB；也可以传 "opfs://" 或内存模式
const db = new PGlite("idb://fag-pg");
await db.waitReady;

await db.exec(`
  CREATE TABLE IF NOT EXISTS orders (
    id uuid PRIMARY KEY,
    user_id text NOT NULL,
    amount numeric(12,2) NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now()
  );
  CREATE INDEX IF NOT EXISTS idx_orders_user ON orders(user_id, created_at DESC);
`);

await db.query(
    "INSERT INTO orders (id, user_id, amount) VALUES ($1, $2, $3) ON CONFLICT (id) DO NOTHING",
    [crypto.randomUUID(), "u-42", 128.5],
);

const { rows } = await db.query<{ user_id: string; total: string }>(
    "SELECT user_id, sum(amount)::text AS total FROM orders GROUP BY user_id",
);

事务与参数绑定 ​

PGlite 的 query(sql, params) 使用 PostgreSQL 的 $1 占位符，不要用字符串拼接——既防注入，也让执行计划可复用。

typescript
// [项目内运行] 一个事务内完成「扣库存 + 写订单」，失败整体回滚
await db.transaction(async (tx) => {
    const { rows } = await tx.query<{ stock: number }>(
        "SELECT stock FROM products WHERE id = $1 FOR UPDATE",
        [productId],
    );
    if (!rows[0] || rows[0].stock < quantity) throw new Error("库存不足");
    await tx.query("UPDATE products SET stock = stock - $1 WHERE id = $2", [quantity, productId]);
    await tx.query("INSERT INTO orders (id, user_id, amount) VALUES ($1, $2, $3)", [
        crypto.randomUUID(),
        userId,
        amount,
    ]);
});

与后端一致性的取舍 ​

  • 能用：数据类型、约束、jsonb、窗口函数、CTE、ON CONFLICT；
  • 要验证：扩展（pgvector、postgis 等）需要额外 WASM 包，并非所有 PG 扩展都能编译；
  • 不要假设：权限、角色、COPY、逻辑复制这些服务端能力在浏览器里没有对应实现。

边界 ​

  • 首次加载要下载数 MB WASM，首屏别同步初始化；
  • idb:// 与 opfs:// 都是本地持久化，但多标签页并发写没有服务端锁，建议单写者；
  • 版本升级要自己做迁移，PGlite 不会自动改你的表结构。

133.4 DuckDB WASM：浏览器里的列式分析 ​

DuckDB 是列式引擎，优势在扫描与聚合：直接读 Parquet/CSV、按列裁剪、向量化执行。它不适合当业务 CRUD 库——单条 INSERT 的开销远高于行式引擎。

加载与查询远程 Parquet ​

typescript
// 文件: examples/133-03-duckdb-parquet.ts
import * as duckdb from "@duckdb/duckdb-wasm";

const bundles = duckdb.getJsDelivrBundles();
const bundle = await duckdb.selectBundle(bundles);
const worker = new Worker(bundle.mainWorker!);
const logger = new duckdb.ConsoleLogger(duckdb.LogLevel.WARNING);
const db = new duckdb.AsyncDuckDB(logger, worker);
await db.instantiate(bundle.mainModule, bundle.pthreadWorker);

const conn = await db.connect();
await db.registerFileURL(
    "orders.parquet",
    "https://example.com/data/orders.parquet",
    duckdb.DuckDBDataProtocol.HTTP,
    false,
);

const result = await conn.query(`
  SELECT region, count(*) AS orders, sum(amount) AS gmv
  FROM read_parquet('orders.parquet')
  WHERE created_at >= DATE '2026-01-01'
  GROUP BY region
  ORDER BY gmv DESC
  LIMIT 20
`);

结果怎么用 ​

conn.query() 返回 Arrow Table，可以用 toArray() 转成对象数组，也可以直接交给 Arrow/可视化库做零拷贝消费。大结果集不要 toArray() 全量展开，优先在 SQL 里 LIMIT 或聚合。

typescript
// [项目内运行] 只取需要的列，避免把整张表搬进 JS 堆
const table = await conn.query(`
  SELECT region, sum(amount) AS gmv
  FROM read_parquet('orders.parquet')
  GROUP BY region
`);
for (const row of table.toArray()) console.log(row.region, Number(row.gmv));

适用与不适用 ​

适合不适合
本地打开 CSV/Parquet 做预览与统计高频单条写入的业务库
离线报表、漏斗、分组聚合需要强事务与行级锁的订单系统
与 Arrow 生态对接的数据探索移动端超大文件全量扫描

边界 ​

  • 远程文件必须允许 CORS，否则 registerFileURL 读取失败；
  • 列式引擎吃内存，移动端要限制扫描文件大小与并发查询数；
  • getJsDelivrBundles() 依赖 CDN，生产建议自托管 WASM 并固定版本。

133.5 建模、索引与迁移 ​

浏览器内数据库没有 DBA，schema 演进必须自己兜住。原则与 132.6 一致：版本只前进、每个版本一个事务、失败整条回滚、旧客户端不解析新格式。

用 schema_migrations 管版本 ​

typescript
// 文件: examples/133-05-db-migrate.ts
type Migration = { version: number; name: string; up: string };

export async function migrate(db: PGlite, list: Migration[]): Promise<number[]> {
    await db.exec(`
        CREATE TABLE IF NOT EXISTS schema_migrations (
            version integer PRIMARY KEY,
            name text NOT NULL,
            applied_at timestamptz NOT NULL DEFAULT now()
        );
    `);

    const { rows } = await db.query<{ version: number }>(
        "SELECT version FROM schema_migrations ORDER BY version",
    );
    const applied = new Set(rows.map((r) => r.version));
    const ran: number[] = [];

    for (const migration of [...list].sort((a, b) => a.version - b.version)) {
        if (applied.has(migration.version)) continue;
        // 一个版本一个事务：失败整条回滚，不会留下半张表
        await db.transaction(async (tx) => {
            await tx.exec(migration.up);
            await tx.query("INSERT INTO schema_migrations (version, name) VALUES ($1, $2)", [
                migration.version,
                migration.name,
            ]);
        });
        ran.push(migration.version);
    }
    return ran;
}

SQLite WASM 可以用 PRAGMA user_version 做同样的事：读当前版本 → 在事务里执行对应迁移 → 写回新版本。两种方式的共同点是迁移记录与业务变更在同一个事务里，不能先改表再记账。

索引设计 ​

查询形态索引说明
WHERE user_id = ? ORDER BY created_at DESC(user_id, created_at DESC)复合索引顺序与查询一致，避免额外排序
WHERE status = ? AND updated_at > ?(status, updated_at)等值列在前、范围列在后
只取少数列的高频查询覆盖索引（把列放进索引）避免回表，但会增加写放大
模糊搜索全文索引 / 倒排LIKE '%x%' 用不上普通 B-Tree

索引不是越多越好：每个索引都会拖慢写入、增大库文件。上线前用 EXPLAIN QUERY PLAN（SQLite）或 EXPLAIN ANALYZE（PGlite）确认真的走了索引。

多标签页迁移 ​

两个标签页同时启动会重复执行迁移。用 Web Locks 串行化：

typescript
// [项目内运行] 迁移必须持有跨标签页排他锁
await navigator.locks.request("fag-db-migrate", { mode: "exclusive" }, async () => {
    await migrate(db, migrations);
});

133.6 Worker 化与线程模型 ​

WASM 数据库的初始化与查询都可能占用几十到几百毫秒。放主线程会阻塞输入、动画与布局。正确做法是数据库实例只存在于 Worker，主线程只发消息。

消息协议 ​

typescript
// 文件: examples/133-04-db-in-worker.ts
const worker = new Worker(new URL("./133-04-db.worker.ts", import.meta.url), { type: "module" });

type Request = { id: number; sql: string; params?: unknown[] };
type Response = { id: number; rows?: unknown[]; error?: string };

function query(sql: string, params?: unknown[]): Promise<unknown[]> {
    const id = Math.floor(Math.random() * 1e9);
    return new Promise((resolve, reject) => {
        const onMessage = (event: MessageEvent<Response>) => {
            if (event.data.id !== id) return;
            worker.removeEventListener("message", onMessage);
            event.data.error ? reject(new Error(event.data.error)) : resolve(event.data.rows ?? []);
        };
        worker.addEventListener("message", onMessage);
        worker.postMessage({ id, sql, params } satisfies Request);
    });
}

Worker 侧：

typescript
// 文件: examples/133-04-db.worker.ts
import { PGlite } from "@electric-sql/pglite";

const db = new PGlite("idb://fag-worker-pg");
await db.waitReady;

self.onmessage = async (event: MessageEvent<Request>) => {
    const { id, sql, params } = event.data;
    try {
        const result = await db.query(sql, params);
        (self as unknown as Worker).postMessage({ id, rows: result.rows } satisfies Response);
    } catch (error) {
        (self as unknown as Worker).postMessage({
            id,
            error: error instanceof Error ? error.message : String(error),
        } satisfies Response);
    }
};

四个必须处理的细节 ​

  1. request id：并发查询必须按 id 配对，否则结果串台；
  2. 错误回传：Worker 内异常不自动传到主线程，Promise 会永远 pending；
  3. 崩溃重启：Worker 崩溃后要重建实例、重放未完成请求；
  4. 大量结果：优先传 ArrayBuffer / Arrow IPC 并 transfer，不要 postMessage 整个对象图。

线程与响应头 ​

DuckDB 的 pthreadWorker、SQLite 的多线程模式都依赖 SharedArrayBuffer。页面需要：

text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp

缺任一个，SharedArrayBuffer 不可用，多线程 bundle 会退化或直接失败。跨域资源（WASM、CDN）也要带 Cross-Origin-Resource-Policy 或 CORS 头。

133.7 体积、性能与容量 ​

加载策略 ​

  • 动态导入：await import("@electric-sql/pglite") 放在路由进入或用户触发后，别进首屏；
  • 固定版本：WASM 文件名带版本，自托管并用长缓存；升级走显式版本号；
  • 缓存 WASM：用 Cache Storage 缓存 .wasm 与 worker 脚本，见 132.8 OPFS 与文件型数据；
  • 按需引擎：CRUD 场景只需 SQLite/PGlite，不要因为「以后可能分析」把 DuckDB 也打进包。

写入与查询优化 ​

问题处理
逐条 INSERT 慢单事务批量插入；PGlite 拼多值 VALUES，SQLite 用 prepare
查询全表扫描建复合索引，EXPLAIN 验证执行计划
返回大结果集SQL 层 LIMIT / 聚合；Worker 传输用可转移对象
首查慢预编译语句 + 预热关键查询；避免每次重建连接
多标签页争抢navigator.locks 单写者，读副本可各自持有

基准怎么写才可信 ​

typescript
// 文件: examples/133-06-db-benchmark.ts
const idb = await benchIDB();
const pg = await benchPGlite();
console.table({
    IndexedDB: { writeMs: Math.round(idb.write), readMs: Math.round(idb.read) },
    PGlite: { writeMs: Math.round(pg.write), readMs: Math.round(pg.read) },
});

基准只做同机对比，不设绝对阈值：设备、存储压力、浏览器版本都会影响结果。更重要的是记录数据量、批量大小与查询形态，否则数字无法复现。

容量治理 ​

  • 用 navigator.storage.estimate() 看整站用量，persist() 申请持久化（见 25.10 浏览器专属高频 API 速览）；
  • 数据库文件也要纳入分层淘汰：缓存表可重建，用户数据与离线队列不可静默删除；
  • 提供「导出 / 导入」能力，用户清站点数据后至少能恢复；
  • 监控库文件增长，定期 VACUUM（SQLite）或导出重建，避免碎片长期累积。

它不能替代什么 ​

  • 不能替代服务端数据库：没有多用户并发控制、备份、审计与权限；
  • 不能保证数据不丢：清站点数据、配额回收、浏览器故障都会影响本地库；
  • 不能解决同步冲突：多设备一致性仍需 CRDT/OT 或服务端版本号，见 43.6 协同编辑入门。

133.9 自测题 ​

1. 什么情况下不该用浏览器内数据库？【基础】

只需要按 key 存取少量结构化对象、查询简单、数据量小的时候。IndexedDB 更轻、无需下载 WASM，维护成本更低；引入数据库要有明确的 SQL/聚合需求。

2. SQLite WASM 的 SAH Pool VFS 解决什么问题？【基础】

主线程只能异步访问 OPFS，而 SQLite 需要同步文件 IO。SAH Pool 预先申请一组同步访问句柄并池化，让数据库能在 Worker 中高效同步读写，同时保持 OPFS 持久化。

3. 为什么批量写入要 `prepare` 而不是循环 `exec`？【基础】

exec 每次都重新解析 SQL；prepare 只解析一次，后续 bind + stepReset 复用语句，配合事务能显著降低写入开销。

4. PGlite 的 `idb://` 和 `opfs://` 有什么区别？【基础】

两者都是本地持久化：idb:// 把数据存进 IndexedDB，兼容性更好；opfs:// 存进源私有文件系统，文件语义更直接。选择取决于目标浏览器与是否需要与 OPFS 其他文件共存。

5. DuckDB WASM 为什么不适合当业务 CRUD 库？【进阶】

它是列式分析引擎，优化的是批量扫描与聚合；高频单条写入、更新、删除不是它的强项，事务与行级并发控制也不如行式数据库。

6. 迁移为什么必须「一个版本一个事务」？【进阶】

多个版本放在一个大事务里，任一语句失败会导致全部回滚，难以定位；分开后每个版本要么完整生效要么完全不生效，迁移记录与表结构始终一致。

7. Worker 消息为什么必须带 request id？【进阶】

并发查询的返回顺序不确定，没有 id 就无法把结果配对到对应 Promise，会出现「A 的查询拿到 B 的结果」。id 也是超时与重放机制的索引。

8. 为什么数据库实例不要放在主线程？【进阶】

WASM 初始化、查询编译与大量结果序列化都会占用主线程，造成输入延迟、动画掉帧。放 Worker 后主线程只负责消息收发，UI 保持流畅。

9. `SharedArrayBuffer` 不可用时会发生什么？【挑战】

多线程 WASM bundle 无法工作，DuckDB 的 pthreadWorker、SQLite 的多线程模式会退化或初始化失败。需要检查 COOP/COEP 响应头与跨域资源策略。

10. 浏览器内数据库如何与多设备同步？【挑战】

本地库只是副本。需要业务层记录变更日志（outbox），与服务端版本号或 CRDT 合并；不能假设「本地 SQL 执行成功」等于「多端一致」。
