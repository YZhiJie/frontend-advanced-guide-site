# EP.62 一套代码跑多端

> 对应正文：[88-uniapp-cross-platform.md](../88-uniapp-cross-platform.md)（88.1 UniApp 架构 / 88.2 条件编译 / 88.3 平台 API 抽象层）· 示例：`examples/88-01-uniapp-cross-platform.ts`

## 剧情回顾

- **第 1 格**：H5、小程序、App、iOS、Android 五端各写一套，发版要同步 5 次，团队苦不堪言。
- **第 2 格**：码叔揭秘条件编译——`#ifdef MP-WEIXIN` 包裹小程序代码，编译时其他平台代码被剥离。
- **第 3 格**：像素酱实证 API 抽象层——`storage.set` 一套接口，底层适配各端存储 API。
- **第 4 格**：码叔结案——主包放首屏，非首屏拆分包按需加载，控制小程序包体积。

## 知识点拆解

### 第 1 格 · 跨端开发的痛点

- 每个端一套代码，维护成本 × N；
- 发版要各端同步，容易出现功能不一致；
- 跨端框架（UniApp / Taro / React Native）的核心价值：**一套代码编译到多端**。

### 第 2 格 · 条件编译

```ts
// #ifdef MP-WEIXIN
wx.showToast({ title: 'ok' })
// #elifdef H5
alert('ok')
// #endif
```

- **编译期**行为，不是运行时 if；
- 产物里只保留目标平台的代码，无死代码、体积小；
- 常见条件：`MP-WEIXIN`（微信小程序）、`H5`、`APP-PLUS`（App）。

### 第 3 格 · 平台 API 抽象层

- 各端 storage / 路由 / 支付 API 不同；
- 封装统一接口（如 `storage.set`），业务代码不感知平台；
- 新增平台只需实现适配器，业务代码零改动。

### 第 4 格 · 分包策略

- 小程序限制：主包 ≤ 2MB，总包 ≤ 20MB；
- 主包放 tabBar + 首屏页面，非首屏拆分包；
- `preloadRule` 在 WiFi 下预下载分包，减少跳转白屏；
- 独立分包（`independent: true`）不依赖主包，可单独打开。

## 坑点清单

> 🔗 正文对照：[《88.7 本章避坑清单》](../88-uniapp-cross-platform#_88-7-本章避坑清单)

1. 条件编译用运行时 `if (platform === 'mp')` 代替 → 产物残留死代码，应改用 `#ifdef`；
2. 直接调 `wx.setStorage` 等平台 API → 换端就挂，应封装抽象层；
3. 主包塞太多页面超 2MB → tabBar 留主包，其余全拆分包。

## 自测 3 题（含答案）

1. 条件编译是编译期还是运行时？——**编译期，产物里不存在其他平台代码**。
2. API 抽象层解决什么问题？——**隔离平台差异，业务代码不关心底层实现**。
3. 小程序主包和总包的大小限制？——**主包 ≤ 2MB，总包 ≤ 20MB**。
