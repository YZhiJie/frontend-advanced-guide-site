# EP.31 排序大比武

> 对应正文：[22-frontend-data-structures.md](../22-frontend-data-structures.md)（22.8 排序算法的比武大会）· 示例：`data-structures/examples/22-09-sorting.ts`

## 剧情回顾

- **第 1 格**：像素酱做表格排序，`[10, 9, 1].sort()` 竟得到 `[1, 10, 9]`，分数列当场翻车。
- **第 2 格**：码叔揭秘——`sort()` 默认按字符串字典序；`O(n²)` 三兄弟（冒泡/选择/插入）对阵 `O(n log n)` 三剑客（归并/快排/堆排）。
- **第 3 格**：标签君演示快排一次 partition：数组 `[3,7,1,8,2,6]`，pivot 选 6，双指针从两端扫描交换，pivot 归位后左右递归。
- **第 4 格**：码叔结案——V8 的 `sort` 是 TimSort（短数组插入、长数组归并），业务别手写，并给出三大坑点。

## 知识点拆解

### 第 1 格 · sort 的字典序陷阱

```js
[10, 9, 1].sort() // → [1, 10, 9]
```

- `Array.prototype.sort()` 不传比较器时，会把元素**转成字符串**再按 UTF-16 码元比较；
- `"10" < "9"` 因为 `"1" < "9"`，导致 10 排在 9 前面；
- 修复：`arr.sort((a, b) => a - b)`，比较器返回负数/零/正数决定顺序。

### 第 2 格 · 六路选手

| 家族 | 算法 | 平均复杂度 | 特点 |
| ---- | ---- | ---- | ---- |
| O(n²) | 冒泡、选择、插入 | n² | 实现简单；插入在近乎有序时接近 O(n) |
| O(n log n) | 归并、快排、堆排 | n log n | 大数据主力；归并稳定，快排原地，堆排不占栈 |

- 归并：分治 + 合并，稳定但需要 `O(n)` 辅助空间；
- 快排：分区 + 递归，原地不稳定，平均最快；
- 堆排：建堆 + 逐个取顶，原地不稳定，最坏也 `O(n log n)`。

### 第 3 格 · 快排 partition 走查

数组 `[3,7,1,8,2,6]`，选末尾 6 为 pivot：
1. `j` 从左扫到右，遇到比 6 小的就换到 `i` 区域；
2. `1`、`2` 依次被换到左侧；
3. 扫描结束后把 pivot 与 `i+1` 位置交换；
4. 结果 `[3,1,2 | 6 | 7,8]`，pivot 归位，左右子数组递归同样处理。

### 第 4 格 · V8 的 TimSort

- **短数组（≤22）**：直接插入排序；
- **长数组**：先跑插入整理出有序 run，再用归并合并；
- 业务代码**不要手写排序**，`sort` 已针对各种分布做过优化，且是稳定排序。

## 坑点清单

> 🔗 正文对照：[《22.11 本章避坑清单》](../22-frontend-data-structures#_22-11-本章避坑清单)

1. **数字排序不传比较器**：字典序导致 `10` 排在 `9` 前面，必须写 `(a, b) => a - b`；
2. **把 sort 当成纯函数**：`sort()` 会**原地修改**原数组，需要保留原数组时先 `slice()` 或 `[...arr]` 再排；
3. **稳定性选错算法**：需要稳定排序（如同分保持原顺序）时不能用快排/堆排，应选归并或直接用原生 `sort`；
4. **对象数组比较器写错**：`sort((a, b) => a.score - b.score)`，别写成 `a - b` 导致 NaN。

## 自测 3 题（含答案）

1. **为什么 `[10,9,1].sort()` 结果是 `[1,10,9]`？**——默认按字符串字典序比较，`"10"` 的首字符 `"1"` 小于 `"9"`；必须传 `(a,b) => a-b` 数字比较器。
2. **快排和归并排序的核心区别是什么？**——快排原地、不稳定、平均 `O(n log n)`；归并稳定、需要 `O(n)` 辅助空间，最坏情况也是 `O(n log n)`。
3. **V8 的 `Array.prototype.sort` 用的是什么算法？**——TimSort：短数组（≤22 个元素）用插入排序，长数组拆成有序 run 后用归并排序合并，且稳定。
