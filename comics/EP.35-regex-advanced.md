# EP.35 正则高级用法通关

> 对应正文：[01-javascript-advanced.md](../01-javascript-advanced.md) 1.15 节 · 示例：`examples/01-37-regex-advanced.ts`

## 剧情回顾

- **第 1 格**：像素酱用 `/<.+>/` 提取标签，结果整串被贪婪吞光；换成惰性 `/<.+?>/` 才停在第一个 `>`。贪婪是"先吃满再回吐"，惰性是"满足即停"。
- **第 2 格**：码叔拆出分组三兄弟：`(x)` 捕获存值占下标、`(?:x)` 只分组不存、`(?<n>x)` 命名挂 `groups`；再配 `\1`/`\k<n>` 反向引用与 `$1`/`$<n>` 重排文本。
- **第 3 格**：标签君实测四种零宽断言 `?= ?! ?<= ?<!`——只看位置不吃字符，千分位与密码强度校验都是位置组合拳。
- **第 4 格**：码叔结案：贪婪遇嵌套跨标签吞并、嵌套量词指数回溯 ReDoS、负向先行回溯截尾、ES2025 重复命名组需特性检测——坑全在回溯上。

## 知识点拆解

### 第 1 格 · 贪婪与惰性：同一个量词，两种策略

量词 `* + ? {m,n}` 默认**贪婪**：先尽量多吃，匹配不下去再逐字符回吐（回溯）；加 `?` 变**惰性**：刚好满足就停。`'<div><span>hi</span></div>'.match(/<.+>/)` 从 `<` 一路吃到整串最后一个 `>`，返回整串；`/<.+?>/` 见到第一个 `>` 就停，返回 `['<div>']`。

**关键认知**：贪婪的代价是回溯。嵌套量词如 `(a+)+b` 遇到 `"aaa...c"` 会指数级回溯（ReDoS），生产环境要么改写模式，要么限制输入长度。

### 第 2 格 · 分组三兄弟与反向引用

| 语法 | 名字 | 作用 |
| ---- | ---- | ---- |
| `(x)` | 捕获组 | 存子表达式结果，按 `match` 下标取（第 0 项是整体） |
| `(?:x)` | 非捕获组 | 只分组不保存，不占下标，语义更清晰 |
| `(?<n>x)` | 命名组 | 结果挂在 `m.groups.n`，可读性远好于魔法下标 |

- **反向引用 `\1`**：引用第 1 组**实际匹配到的文本**，不是把分组里的模式再匹配一遍——`(\w+)-\1` 匹配 `ab-ab`，`<(\w)>.*</\1>` 要求开合标签名一致；
- **replace 侧 `$1` / `$<name>`**：引用捕获组重排文本，如 `'2026-10-18'.replace(/(\d{4})-(\d{2})-(\d{2})/, '$3/$2/$1')`；
- **`matchAll` + `/g`**：遍历全部匹配，每项都带完整分组信息，是 `exec` 循环的现代替代品。

### 第 3 格 · 四种零宽断言

断言只"看一眼"位置，不"吃"任何字符：

| 断言 | 方向 | 语义 |
| ---- | ---- | ---- |
| `(?=X)` | 正向先行 | 右侧必须是 X |
| `(?!X)` | 负向先行 | 右侧不能是 X |
| `(?<=X)` | 正向后行 | 左侧必须是 X |
| `(?<!X)` | 负向后行 | 左侧不能是 X |

组合拳两例：千分位 `/\B(?=(\d{3})+(?!\d))/g`（非单词边界 + 右侧是完整 3 位组）；密码强度 `/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?!.*\s)\S{8,}$/`——每个 `(?=...)` 都从同一起点检查，等价于"同时满足"的多道关卡。

### 第 4 格 · 高频易错点

1. **负向先行会"截尾"**：`/\d+(?!元)/g` 匹配 `'100元'`，`100` 想躲开元，回溯退到 `10` 就满足了——所以输出 `['10', ...]`。想要"完整数字后面不是元"要换思路（如 `\d+(?![元])` 配合边界或改用后行断言组合）；
2. **贪婪 + 嵌套结构会跨标签吞并**：解析 HTML 请用 DOM API，正则只做行内简单切分；
3. **JS 后行断言支持变长**：`(?<=¥|RMB)` 这种多长度分支合法（多数语言只支持定长）。

## 坑点清单

> 🔗 正文对照：[《1.19 本章避坑清单》](../01-javascript-advanced#_1-19-本章避坑清单)

1. **贪婪遇嵌套跨标签吞并**：`/<.+>/` 会从第一个 `<` 吃到最后一个 `>`，切 HTML 必须用 DOM API；
2. **嵌套量词指数回溯（ReDoS）**：`(a+)+b` 类模式遇不匹配长串会卡死，生产环境限制长度或改写模式；
3. **负向先行回溯截尾**：`\d+(?!元)` 会把 `100` 截成 `10` 来满足条件，结果集与直觉相反，需理解回溯机制；
4. **`\1` 误当"再匹配一遍模式"**：它引用的是第 1 组实际捕获的文本，不是模式本身；
5. **ES2025 重复命名捕获组**：同分支复用组名是新语法，实测 Node v24 仍抛 `Duplicate capture group name`，必须特性检测后降级（用不同组名）。

## 自测 3 题（含答案）

1. **为什么 `/<.+>/` 会匹配整串 `'<div><span>hi</span></div>'`？怎么改？**——量词 `+` 默认贪婪：从第一个 `<` 起，`.` 一路吃到整串最后一个 `>` 才满足；中途每个 `>` 它都"还能继续吃"，所以不停。改成惰性 `/<.+?>/`（量词后加 `?`），刚好满足第一个 `>` 就停，返回 `['<div>']`。
2. **`/\d+(?!元)/g` 匹配 `'100元'` 得到 `10` 而不是空，为什么？**——负向先行只要求"当前位置右侧不是元"。`100` 整体后面是元不满足，但引擎会回溯：退到 `10` 时右侧是 `0`，满足条件，于是捕获 `10`。断言约束的是"匹配结束的位置"，不是"整个数字"。
3. **千分位正则 `/\B(?=(\d{3})+(?!\d))/g` 是怎么工作的？**——`\B` 选在数字内部（非单词边界）的位置；`(?=(\d{3})+(?!\d))` 要求从该位置到数字末尾恰好由若干完整 3 位组构成（`(?!\d)` 防止 3 位组后面还拖着数字，保证从右往左每 3 位一组）；两个零宽条件叠加，在每个合法插入点插入 `,`，`'12345678'` 即变 `'12,345,678'`。
