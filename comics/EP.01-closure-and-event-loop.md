# EP.01 闭包与事件循环

> 对应正文：[01-javascript-advanced.md](../01-javascript-advanced.md)（1.1 执行上下文与作用域 / 1.2 闭包 / 1.5 异步编程与事件循环 / 1.6 内存管理）· 示例：`examples/01-25-engine-pipeline.js`、`examples/01-03-closure-wallet.ts`、`examples/01-12-event-loop.js`

## 剧情回顾

- **第 1 格**：标签君发现 `wallet()` 已经 return，里面的 `money` 却还活着——这就是**闭包**：函数 + 它出生时的词法作用域。
- **第 2 格**：码叔先亮编译流水线（源码 → token → AST → 字节码），再画事件循环的指挥棒——同步栈清空 → 清空全部微任务 → 取一个宏任务。
- **第 3 格**：像素酱用 `var` / `let` 经典题实证：回调排队执行时，`var` 全局只有一个 `i`，`let` 每轮新建作用域。
- **第 4 格**：码叔结案——闭包的代价是"拖着作用域不放手"，要防内存泄漏。

## 知识点拆解

### 第 1 格 · 闭包是什么

- 函数定义时**记住**所在词法作用域的引用，即使作用域已经执行完毕；
- `money` 存活在堆内存中，外部无法直接访问，只能通过返回的函数操作——这是天然的**私有变量**；
- 项目示例 `01-03-closure-wallet.ts` 就是这个钱包模型。

### 第 2 格 · 先编译，再循环

第 2 格顶部四个芯片是代码进调用栈之前的**编译流水线**：

- 源码 → **词法分析**切出 token → **语法分析**组织成 AST → V8 Ignition 编译为**字节码**解释执行，热点函数交给 TurboFan JIT 优化为机器码；
- 进入作用域先经历**创建阶段**：`var` 初始化为 `undefined`、`let/const` 只绑定进 TDZ，然后才逐行执行——提升与死区都发生在这一步；
- Babel / ESLint / Prettier / SWC 的本质都是"源码 → AST → 改写/检查 → 生成代码"；
- `SyntaxError` 是解析期错误（整段脚本一行都不执行），`ReferenceError` 是执行期错误。

事件循环的调度顺序：

1. 同步代码在调用栈执行；
2. 栈清空后，**清空整个微任务队列**（`Promise.then`、`queueMicrotask`、`MutationObserver`）；
3. 取**一个**宏任务（`setTimeout` / `setInterval` / I/O）执行；
4. 浏览器环境在渲染前执行 `requestAnimationFrame`，然后回到第 2 步。

### 第 3 格 · var/let 经典题

```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2
```

- `var` 只有一个函数级绑定，回调执行时循环早已结束，`i === 3`；
- `let` 在**每轮迭代**创建新的词法环境，每个回调闭包抓住自己的 `i`。

### 第 4 格 · 闭包的代价

- 闭包引用大数组 / DOM 节点，且长期不释放 → 内存泄漏（见正文 1.6）；
- 防抖 `debounce`、节流 `throttle`、`once` 全靠闭包"记账"，这正是 `examples/01-20-debounce-throttle.ts` 的原理。

### 延伸 · 跑一遍真实模拟器

第 2 格的流水线在正文 1.1 有完整五阶段时间线；`node examples/01-25-engine-pipeline.js` 用约百行代码复刻"字符流 → token → AST → 创建/执行阶段"主干，直接打印各阶段产物、TDZ 状态，以及 SyntaxError（解析期，整段不执行）与 ReferenceError（执行期）的对照。

## 坑点清单

> 🔗 正文对照：[《1.19 本章避坑清单》](../01-javascript-advanced#_1-19-本章避坑清单)

1. 定时器、事件监听器在组件卸载 / 逻辑结束后不清理 → 闭包常驻内存；
2. 循环 + 异步回调误用 `var`，输出"最后一次"的值；
3. 以为 `setTimeout(fn, 0)` 立即执行——它只是进入了宏任务队列。

## 自测 3 题（含答案）

1. 微任务和宏任务的执行顺序？——**同步栈清空后先清空全部微任务，再取一个宏任务**。
2. 为什么 `let` 能修复循环打印问题？——**每轮迭代生成新的词法作用域，回调各自捕获当轮的 i**。
3. 闭包一定导致内存泄漏吗？——**不一定；只有闭包持有的大对象生命周期长于需要时才泄漏，及时解除引用即可回收**。
