# EP.63 RAG 让 AI 不再胡说

> 对应正文：[89-rag-knowledge-base.md](../89-rag-knowledge-base.md)（89.1 RAG 原理 / 89.2 文档分块与 embedding / 89.3 对话记忆）· 示例：`examples/89-01-rag-knowledge-base.ts`

## 剧情回顾

- **第 1 格**：用户问产品营收，AI 凭空编数——大模型幻觉。
- **第 2 格**：码叔揭秘 RAG——先检索私有文档，再把上下文喂给 LLM 生成。
- **第 3 格**：像素酱实证分块与 embedding——文档切块转向量，余弦相似度取 Top-K。
- **第 4 格**：码叔结案——多轮对话用滑动窗口+摘要管理上下文长度。

## 知识点拆解

### 第 1 格 · 幻觉的根源

- LLM 训练数据有截止日期，不知道最新/私有信息；
- 没有事实依据时会"一本正经地胡说"；
- 解决思路：给模型提供可参考的上下文。

### 第 2 格 · RAG 流程

```
用户问题 → 向量化 → 向量库检索 Top-K → 拼装 Prompt → LLM 生成
```

- RAG = Retrieval-Augmented Generation；
- 不微调模型，而是检索知识注入 Prompt；
- 模型只负责阅读理解和生成，降低幻觉。

### 第 3 格 · 分块与向量检索

- 文档按 token 切块（如 512 token + 50 重叠），避免语义断裂；
- 每块转 embedding 向量存向量数据库（Milvus / Pinecone / pgvector）；
- 查询时算余弦相似度，取 Top-K 相关块；
- 可加 Rerank（交叉编码器）精排提升精度。

### 第 4 格 · 对话记忆管理

- 滑动窗口：保留最近 N 轮对话；
- 摘要压缩：历史对话压缩成一句话；
- 向量记忆：用语义检索找相关历史；
- Token 预算要分配给系统提示、检索内容、历史、回答。

## 坑点清单

> 🔗 正文对照：[《89.7 本章避坑清单》](../89-rag-knowledge-base#_89-7-本章避坑清单)

1. 分块无重叠 → 语义被切断，检索召回率低；
2. Top-K 太少或太多 → 少了漏信息，多了塞爆 Prompt 还引入噪音；
3. 不做对话窗口管理 → 多轮后 Prompt 超限报错。

## 自测 3 题（含答案）

1. RAG 的核心思想是什么？——**不微调模型，检索私有知识注入 Prompt，让模型基于事实生成**。
2. 文档分块为什么要加重叠？——**防止一句话被切成两块导致语义断裂，提升检索召回率**。
3. 多轮对话的上下文管理有哪些策略？——**滑动窗口、摘要压缩、向量记忆，工程上常用窗口+摘要混合**。
