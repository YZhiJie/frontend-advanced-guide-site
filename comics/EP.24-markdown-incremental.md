# EP.24 Markdown 增量渲染

> 对应正文：[21-frontend-ai-interview.md](../21-frontend-ai-interview.md)（21.5 Markdown 增量渲染）· 关联：[7.1 XSS 攻防](../07-security.md#71-xss-跨站脚本攻击)、`examples/07-01-xss-defense.ts`

## 剧情回顾

- **第 1 格**：标签君每收到一个 token 就 `marked.parse(全文)` 并全量替换 innerHTML，代码块颜色乱跳、图片狂闪，长回答直接卡死。
- **第 2 格**：码叔揭秘根因——Markdown 要"看到结尾才能确定开头"：闭合的代码围栏、表格分隔线、括号没到时，当前解析结果随时翻盘。
- **第 3 格**：像素酱实证三板斧：解析降频到 80ms + 未闭合围栏临时补齐 + 已闭合块 keyed memo 冻结，最后一块之外不再重算。
- **第 4 格**：码叔结案——DOMPurify 必须在所有变换之后、注入之前消毒；超长内容上虚拟列表与 Worker。

## 知识点拆解

### 第 1 格 · 流式 Markdown 的特殊矛盾

- 普通渲染：输入完整，解析一次即可；流式渲染：输入持续增长且不完整；
- 每 token 全量解析的总成本随长度叠加，长答案接近 O(n²)；
- 全量替换 innerHTML 还会丢滚动、重载图片、重启 CSS 动画与 Mermaid。

### 第 2 格 · 哪些语法会"翻盘"

| 语法 | 未闭合时的表现 |
| ---- | ---- |
| 围栏代码块 | 代码围栏出现奇数个时，后面的正文全被吃进代码块 |
| 表格 | 分隔线 `---` 未到，行内竖线只是普通文本 |
| 链接/图片 | `[x](url` 未闭合，整段无法成链接 |
| 强调/HTML 块 | `**` 与标签未闭合时行内归属变化 |

严格的"只解析新增部分"极易出错，工业界主流是：**高频对累积全文做幂等重渲染，但让 DOM 变化最小**。

### 第 3 格 · 三板斧与引擎选型

1. **降频**：token 进缓冲，rAF 合批；Markdown 解析每 50~100ms 一次，流结束再做终态解析；
2. **半成品稳定化**：奇数围栏先补一个闭合围栏再解析，或最后一块降级纯 `<pre>`，闭合后再升级高亮；
3. **块级冻结**：按顶层块切分，已闭合块用内容 hash 作 key + memo，重渲染只发生在尾部一块。

- 选型：高频小增量用 marked/markdown-it；React 中等体量用 react-markdown；重 AST 变换用 remark 生态；超大文档用 markdown-wasm 或把解析丢 Worker；
- 代码高亮：流式中轻量处理，定稿再上 Shiki；结果按内容 hash 缓存；KaTeX/Mermaid 在语法闭合后才渲染。

### 第 4 格 · 安全与长文档

- 模型输出不可信：`<img onerror>`、`javascript:` 链接都能借 Markdown 原生 HTML 注入；
- 消毒时机：**所有插件/高亮变换之后、写入 DOM 之前**，用 DOMPurify；react-markdown 配 rehype-raw 时必须加 rehype-sanitize；
- 链接强制 `rel="noopener noreferrer"` 与协议白名单，CSP 兜底；
- 两万字 + 几十段代码：Worker 解析 + 块级 keyed diff + 虚拟列表（视口外 content-visibility）+ 图表/图片懒加载。

## 坑点清单

> 🔗 正文对照：[《21.7.3 常见误区总清单》](../21-frontend-ai-interview#_21-7-3-常见误区总清单)

1. 每 token 全量 parse + innerHTML：O(n²)、闪烁、丢滚动；
2. 未闭合代码块不处理：颜色与结构每帧横跳；
3. 只在解析前消毒或干脆不消毒：插件可二次产出危险节点；
4. 流式期间就渲染 Mermaid：语法没闭合时疯狂报错；
5. 长文档全部进 DOM：节点爆炸，必须窗口化。

## 自测 3 题（含答案）

1. **为什么流式 Markdown 不能"只解析新增部分"？**——块语义依赖结尾（围栏、表格、括号、HTML 块），新 chunk 可能让旧内容归属翻盘；主流做法是对累积全文降频幂等重渲染，配合块级冻结让实际 DOM 变更最小。
2. **代码块高亮闪烁怎么解？**——奇数围栏临时补闭合稳定解析，或尾块先用纯 pre、闭合后升级高亮；已闭合块按 hash key + memo 冻结；Shiki 结果缓存。
3. **XSS 防护的关键点？**——把模型输出当不可信输入；DOMPurify 消毒放在所有变换之后、注入之前；链接协议白名单与 noopener；代码块转义；CSP 兜底。
