# EP.30 图与堆

> 对应正文：[22-frontend-data-structures.md](../22-frontend-data-structures.md)（22.6 图与拓扑排序、22.7 堆与优先级队列）· 示例：`data-structures/examples/22-08-graph.ts`、`data-structures/examples/22-07-heap.ts`

## 剧情回顾

- **第 1 格**：标签君手写构建工具时，模块打包顺序错乱，还撞上 A↔B 循环依赖，调用栈直接爆炸。
- **第 2 格**：码叔揭秘图的数据结构——顶点加边，前端稀疏图最省空间的存法是邻接表 `Map<V, V[]>`。
- **第 3 格**：像素酱实证 Kahn 拓扑排序走查：维护入度表，A（入度 0）先出队，边删除后 B 归 0，最终得到 A→B→C；角落引出任务优先级可用大顶堆。
- **第 4 格**：码叔结案——堆即优先级队列真身，适用模块依赖图/任务调度/TopK 热榜，并给出三大坑点。

## 知识点拆解

### 第 1 格 · 为什么需要依赖图

- 前端工程化中，模块之间存在显式或隐式的依赖关系；
- 手写打包脚本如果不先建图、直接递归加载，极易因为循环引用导致死循环或栈溢出；
- 依赖图还能帮我们发现「哪些模块可以先并行编译、哪些必须串行」。

### 第 2 格 · 图的存储：邻接表

```ts
const graph = new Map<string, string[]>();
function addEdge(v: string, w: string) {
  if (!graph.has(v)) graph.set(v, []);
  graph.get(v)!.push(w);
}
```

- 邻接表适合**稀疏图**（边数远小于顶点平方），空间复杂度 `O(V+E)`；
- 邻接矩阵 `O(V²)` 在模块依赖场景下会浪费大量空位；
- 有向图用一条边 `v → w` 即可表达单向依赖。

### 第 3 格 · Kahn 拓扑排序

算法步骤：
1. 遍历所有边，统计每个顶点的**入度**；
2. 将入度为 0 的顶点入队；
3. 依次出队，输出到结果数组，并把该顶点的邻接边删除（邻接入度 -1）；
4. 若邻居入度也变为 0，则入队；
5. 最终若结果数组长度 ≠ 顶点数，说明图中**存在环**。

**任务优先级 → 大顶堆**：当同一层有多个入度为 0 的任务，可按权重或优先级用堆取出最大值。

### 第 4 格 · 堆（优先级队列）

- 堆用**完全二叉树**数组实现，`siftUp`/`siftDown` 保持堆性质；
- 大顶堆堆顶是全局最大值，取顶 `O(1)`、插入/删除 `O(log n)`；
- 前端场景：异步任务调度（React Scheduler）、热榜 TopK、合并 K 个有序列表。

## 坑点清单

> 🔗 正文对照：[《22.11 本章避坑清单》](../22-frontend-data-structures#_22-11-本章避坑清单)

1. **入度不归零 = 有环未报**：拓扑排序结束后若结果长度小于顶点数，必须抛异常，否则隐性 Bug 会在运行时爆发；
2. **DFS 递归深会爆栈**：对于深度极大的链式依赖图，递归拓扑排序可能触发 `Maximum call stack size exceeded`，应改用迭代版 Kahn 或尾递归优化；
3. **堆只保证堆顶最值**：弹出堆顶后其余元素并非全局有序，需要全局排序时请用快排/归并，不要逐个弹出堆顶；
4. **邻接表忘了初始化默认值**：`Map.get(v).push(w)` 前务必确认 `v` 已存在数组，否则运行时抛 `Cannot read properties of undefined`。

## 自测 3 题（含答案）

1. **拓扑排序如何判断图中存在环？**——执行完毕后检查结果数组长度是否等于顶点数；若小于，说明有环导致部分顶点入度永远无法归零。
2. **为什么前端模块依赖图更适合邻接表而不是邻接矩阵？**——模块依赖是稀疏图，邻接表空间 `O(V+E)` 远优于邻接矩阵的 `O(V²)`，且遍历邻居更高效。
3. **大顶堆和二叉搜索树在「取最大值」上有什么区别？**——大顶堆取最大值 `O(1)`，但其余元素无序；二叉搜索树中序遍历可得全局有序，但取最大值需要走到最右节点 `O(h)`。
