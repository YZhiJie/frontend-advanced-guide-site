# EP.64 画布上的节点连线

> 对应正文：[90-node-editor-canvas.md](../90-node-editor-canvas.md)（90.1 图数据模型 / 90.2 连线合法性 / 90.3 环检测 / 90.4 自动布局）· 示例：`examples/90-01-node-editor-canvas.ts`

## 剧情回顾

- **第 1 格**：节点连线形成环，数据死循环卡死浏览器。
- **第 2 格**：码叔揭秘图模型——Node + Edge，连线前做合法性校验。
- **第 3 格**：像素酱实证 DFS 三色法环检测。
- **第 4 格**：码叔结案——用 dagre 自动布局，视口支持缩放平移。

## 知识点拆解

### 第 1 格 · 环的危害

- 节点编辑器本质是图结构；
- 如果存在环（A→B→C→A），执行时数据无限循环；
- 解决方案：保证图是 DAG（有向无环图）。

### 第 2 格 · 图数据模型

```ts
Node { id, type, position, data }
Edge { id, source, target, sourceHandle, targetHandle }
```

- React Flow / X6 的核心数据结构；
- 连线校验：不能连自己、handle 类型匹配、加边后无环。

### 第 3 格 · 环检测（DFS 三色法）

- 0=未访问，1=访问中，2=已完成；
- DFS 时遇到状态为 1 的节点 = 有环；
- 时间复杂度 O(V+E)。

### 第 4 格 · 自动布局与视口

- dagre：有向图自动分层布局（rankdir 控制方向）；
- 视口：zoom 缩放、pan 拖拽、fitView 自适应、mini-map 小地图。

## 坑点清单

> 🔗 正文对照：[《90.7 本章避坑清单》](../90-node-editor-canvas#_90-7-本章避坑清单)

1. 加边不查环 → 执行死循环卡死；
2. 节点无唯一 key → 渲染异常、连线错位；
3. 大量节点不虚拟化 → 卡顿。

## 自测 3 题（含答案）

1. 节点编辑器的核心数据结构是什么？——**Node 数组 + Edge 数组**。
2. 环检测的 DFS 三色法中，遇到什么状态说明有环？——**遇到"访问中"（inStack）的节点**。
3. 自动布局常用什么库？——**dagre**（有向图分层）或 elkjs。
