## 65.1 浏览器打印能力全景与天花板

### 概念解析

浏览器打印的技术栈只有四块，但每块都有明确边界：

| 能力 | API/CSS | 能做什么 | 做不到什么 |
| --- | --- | --- | --- |
| 触发打印 | `window.print()` / iframe 打印 | 拉起系统打印对话框 | 静默打印（必须用户确认， kiosk 场景靠浏览器 kiosk 模式或 Electron） |
| 打印样式 | `@media print` | 隐藏导航、改排版、强制彩色 | 与屏幕样式完全独立的两套布局（只能覆盖，不能另起炉灶） |
| 页面设置 | `@page` | 纸张尺寸、方向、四边距 | 页眉页脚内容（margin boxes 各浏览器支持参差） |
| 分页控制 | `break-before/after/inside` | 块级断页、防拆分 | 精确到「这一行必须在第 3 页」的绝对分页 |

三条必须先认清的天花板：

1. **页眉页脚是浏览器自留地**：Chrome 的页眉页脚（URL/日期/页码）只能由用户在打印对话框里开关，CSS `@page` 的 margin boxes（`@top-center` 等）至今只有部分浏览器支持。要可控的页眉页脚（公司 logo + 页码 + 机密水印），要么服务端 PDF，要么用「固定定位元素每页重复」的 hack（对滚动式打印有效，但无法精确落在页边距内）。
2. **浏览器缩放与系统缩放会污染物理尺寸**：用户在打印对话框里设了 120% 缩放，你的 mm 就全部失真。套打场景必须在打印说明里锁定 100% 缩放 + 「实际大小」，并把这句话印在预览页面上。
3. **打印样式不是屏幕样式的子集**：屏幕上的深色主题打印出来是墨盒灾难；屏幕的悬浮交互打印出来是死元素。打印样式要当一套独立设计对待（65.2）。

### 典型应用场景

- 合同/报告：多页流式文档，要分页控制与每页页眉——`@page` + `break-inside: avoid` 够用；
- 发票/快递单/证书：预印制纸张上精准落字——套打模板（65.3）；
- 正式对外 PDF（报价单/电子发票）：版式必须跨环境一致——服务端 PDF（65.4），浏览器打印只是开发期的预览手段。

### 最佳实践

- ✅ 打印需求评审时先问三个问题：要不要页眉页脚？纸张是不是预印制的？用户群体会不会调打印缩放？三个「要/是/会」任何一个命中，直接上服务端 PDF；
- ✅ 打印预览页与打印样式同源开发：`@media print` 的每条规则都在预览页可验证；
- ❌ 不要让用户直接对业务页面 `Ctrl+P`——业务页打印出来必然支离破碎，永远提供专门的「打印视图」。

## 65.2 打印样式工程与分页控制

### 概念解析

打印样式表的工程组织：

```css
@media print {
  /* 1. 隐藏非打印元素 */
  nav, .sidebar, .toolbar, .no-print { display: none !important; }
  /* 2. 强制彩色输出（浏览器默认省墨丢背景色） */
  * { print-color-adjust: exact; -webkit-print-color-adjust: exact; }
  /* 3. 字号转物理单位：屏幕 px → 打印 pt（1pt = 1/72in） */
  body { font-size: 10.5pt; } /* 五号字,中文单据默认 */
}
@page {
  size: A4 portrait;         /* 纸张与方向 */
  margin: 15mm 15mm;         /* 四边距,页眉页脚的空间从这里抠 */
}
```

**分页控制**是打印质量的核心。CSS 给的是声明式规则：`break-inside: avoid`（块不拆分）、`break-before: page`（强制换页）。但声明式规则解决不了**确定性分页**问题——「合计行必须和最后一条明细同页」「标题不能孤悬页尾」需要计算。装箱算法（bin packing 的简化版）：按可用页高逐块装箱，`keepWithNext` 块（标题）若与下一块同放超页则提前换页，`unbreakable` 超高块独占一页并告警缩放。

关键单位认知：**打印场景唯一可信的单位是 mm**。`96px = 25.4mm` 是规范定值（1in = 96px = 25.4mm），屏幕的 px 会因设备像素比与缩放漂移，打印介质上的 mm 不会。模板坐标、页高换算、偏移计算全部在 mm 域进行，渲染时再换算。

### 完整代码示例

```typescript
// 文件: examples/65-01-print-pagination.ts（核心节选）
const MM_PER_PX = 25.4 / 96; // 规范定值:96px = 25.4mm
function paginate(blocks: Block[], spec: PageSpec): Page[] {
  for (const b of blocks) {
    // keepWithNext:标题要与下一块同页,否则提前换页（孤行控制）
    const needPair = b.keepWithNext && next ? b.heightPx + next.heightPx : b.heightPx;
    if (b.unbreakable && b.heightPx > limit) { /* 独占一页并告警 */ }
    if (cur.usedPx + needPair > effectiveLimit) { /* 换页 */ }
  }
}
```

> 运行方式：`npx tsx examples/65-01-print-pagination.ts`（mm↔px 规范换算、装箱换页、keepWithNext 孤行控制、unbreakable 独占页，共 7 组硬断言）。

### 最佳实践

- ✅ 表格跨页用原生 `thead` 重复（浏览器自动每页重复表头），配合 `tr { break-inside: avoid }` 防行截断；
- ✅ 页码用 CSS 计数器 hack 或服务端 PDF 生成；浏览器打印对话框自带的页码不可控样式；
- ⚠️ `print-color-adjust: exact` 强制彩色会显著增加墨耗——财务报表的红字该强制，装饰性渐变该放弃，逐元素决策；
- ❌ 不要依赖 `@page` margin boxes 做页眉页脚（60 册：查 Baseline 再定方案）——Chrome 至今未实现 `@top-center`，兼容性不及格。

## 65.3 套打：毫米级定位模板

### 概念解析

套打 = 在**预印制好的纸张**（发票、快递单、结婚证）的指定框里精准落字，纸张上已有印刷内容，打印层只补空白。技术模型：模板定义纸张尺寸 + 字段框坐标（mm），数据填充时逐字段渲染到绝对定位层，整体 `display: none` 于屏幕、`@media print` 显现。

套打的三道质量门：

1. **模板自检**：字段框不得越出纸张、不得互相重叠——重叠意味着落字压到印刷区，是实物事故。自检在模板保存时执行，不等到打印才发现；
2. **数据填充纪律**：缺数据字段记 `missing` 清单供人工确认（套打空白格可能意味着漏填，静默跳过是财务事故）；超长字段按 `maxChars` 截断并标记 `truncated`——截断本身要可视化警告，因为被截掉的可能是金额或名称的关键部分；
3. **对齐校准**：打印机进纸有 1-2mm 物理偏差，模板系统要支持全局偏移补偿（offsetX/offsetY），用测试页（十字线 + 标尺）让用户调准一次后保存到打印机配置。

格式化在模板层完成：金额 `¥1,234.50`、日期 `2026年10月28日`、大写金额「壹仟贰佰叁拾肆元伍角」——格式化函数挂在字段定义上，渲染层拿到的是最终字符串。

### 最佳实践

- ✅ 模板编辑器可视化：底图（单据扫描件）+ 拖拽字段框 + 实时 mm 坐标，业务方可自助维护模板；
- ✅ 模板版本化：同一单据类型的模板演进留历史，重打历史单据用当时的模板版本；
- ⚠️ 不同打印机型号进纸偏差不同——偏移补偿按「打印机 + 纸张」组合存配置，不按用户存；
- ❌ 不要在套打模板里用 px 定义坐标——设计稿的 px 经过屏幕缩放后与原稿 mm 失配，模板域只用 mm。

## 65.4 PDF 导出选型决策

### 概念解析

「导出 PDF」有四条技术路线，按版式保真度与成本排序：

| 路线 | 保真度 | 成本 | 适用 |
| --- | --- | --- | --- |
| 浏览器打印另存 PDF | 中（受打印 CSS 限制） | 零 | 内部工具、用户自助导出 |
| 前端 html2canvas + jsPDF | 低（截图本质，文字不可选、矢量丢失） | 低 | 快速预览分享，不要求正式版式 |
| 前端 pdf-lib 绘制 | 高（真矢量） | 高（手写绘制指令） | 简单单据、不常变版式 |
| 服务端无头浏览器（Puppeteer/Playwright） | 高（与打印同源 HTML） | 中（服务端资源） | **正式报表的事实标准** |
| 服务端模板引擎（wkhtmltopdf/LibreOffice/报表工具） | 高 | 中 | 存量系统、Excel 模板转 PDF |

决策规则：

1. **文字必须可选中/可复制**（合同、发票）→ 排除 html2canvas（它是截图）；
2. **版式必须跨环境一致**（给客户/监管的文件）→ 服务端渲染，用户机器的字体、缩放、浏览器差异全部被服务端钉死；
3. **中文字体**是服务端 PDF 的第一坑：无头浏览器容器必须内置中文字体（Noto Sans CJK），否则满篇豆腐块；字体子集化（只嵌入用到的字）把 10MB 字体压到几百 KB；
4. **大报表分页**：服务端无头浏览器复用打印 CSS 的分页规则，但要显式等待渲染完成（`waitUntil: "networkidle0"` + 图表库动画关闭）再截图，否则图表残缺。

异步导出架构（与 62/63 册联动）：导出请求 → 服务端生成任务 → 完成后通知中心推送下载链接（62 册）→ 下载行为记审计（63 册，导出即高危操作）。同步等 30 秒的导出进度条是上一代方案。

### 最佳实践

- ✅ 报表 HTML 模板屏幕/打印/PDF 三端同源：一套模板 + `@media` 分场景覆盖，版式漂移只在一处修；
- ✅ 服务端 PDF 加并发与超时护栏：无头浏览器实例池上限 + 单任务 60s 超时 + 失败重试队列；
- ⚠️ html2canvas 对 `position: fixed`、iframe、跨域图片支持有坑，用之前先拿真实页面验证；
- ❌ 不要把 PDF 生成塞在请求-响应同步链路里——大报表生成 30s+，网关超时与用户刷新会造成重复任务（幂等任务 ID + 通知下发）。

## 65.5 自测题

<details>
<summary><b>1. 【基础】浏览器打印的三个天花板是什么？命中任何一个应该转向什么方案？</b></summary>

① 页眉页脚不可控（@page margin boxes 浏览器支持参差，对话框自带的页眉页脚样式不可定制）；② 打印缩放污染物理尺寸（用户设 120% 缩放，mm 定位全部失真）；③ 无静默打印（必须用户确认）。命中任何一个转向服务端 PDF：无头浏览器（Puppeteer/Playwright）把版式、字体、页眉页脚全部钉死在服务端，浏览器打印退化为开发预览手段。评审三问：要不要精确页眉页脚？是不是预印制纸张？用户会不会调缩放？
</details>

<details>
<summary><b>2. 【基础】为什么打印场景的唯一可信单位是 mm？px 在打印中出了什么问题？</b></summary>

规范定值 96px = 25.4mm 保证了 mm 与物理介质的映射是稳定的。px 的问题在于它是屏幕单位：设备像素比、系统缩放、打印对话框缩放都会让 px 到纸张的映射漂移——屏幕上 100px 的框，在 120% 打印缩放下落到纸上就不是你算的位置。工程纪律：模板坐标、页高、偏移补偿全部在 mm 域计算，只在最终渲染到屏幕预览时换算 px，且预览要声明「以实际打印为准」。
</details>

<details>
<summary><b>3. 【基础】装箱分页算法中 keepWithNext 解决什么问题？不处理会怎样？</b></summary>

解决「孤行/孤题」问题：表格标题恰好落在页尾，内容行全在下一页——读者看到一页底部孤零零一个标题。keepWithNext 让标题与下一块作为一个整体参与装箱：放得下「标题+首行」才放，放不下标题也提前换页。不处理的话长报表每几页就出现标题孤悬、合计行与明细分离的版式事故。Word 里的「与下段同页」、CSS 的 break-after: avoid 是同一诉求。
</details>

<details>
<summary><b>4. 【进阶】套打模板为什么要在保存时做越界与重叠自检？放到打印时报错不行吗？</b></summary>

套打的错误成本是实物成本：打印到预印制发票上的错位字无法撤回，发票作废重开有财务流程代价。保存时自检（字段框越出纸张、两两矩形重叠、maxChars 非法）把事故拦截在模板进入生产之前——这是「错误左移」原则：越晚发现的错误成本越高，模板期的错误是零成本的。打印时还要再做一次（防御模板被绕过编辑），但那时报错只应是兜底告警。同理，缺数据字段记 missing 清单而不是静默空白——发票上少一个字段可能是重大漏项。
</details>

<details>
<summary><b>5. 【进阶】html2canvas + jsPDF 方案的根本局限是什么？什么需求下它就直接出局？</b></summary>

html2canvas 的本质是把 DOM 重绘成位图再塞进 PDF——输出的是图片不是文档。由此出局的需求：① 文字需要可选中可复制（合同审阅要复制条款）；② 需要矢量缩放（打印放大后位图模糊）；③ 文件体积敏感（位图远大于矢量文本）；④ 可访问性（读屏器读不出图片里的字）。它只配用于「快速分享预览」这种非正式场景。正式对外文件（给客户/监管/法庭）必须真矢量：前端 pdf-lib 手写绘制，或服务端无头浏览器/模板引擎生成。
</details>

<details>
<summary><b>6. 【进阶】服务端无头浏览器生成 PDF 为什么要"等待渲染完成 + 关闭动画"？不等会发生什么？</b></summary>

无头浏览器截图的时刻由代码控制，而页面渲染是异步的：字体加载、接口数据、ECharts 图表绘制动画都需要时间。不等待就截图会得到残缺 PDF：图表只有坐标轴没有数据线（动画才播到一半）、字体回退成默认衬线体、异步区块空白。正确姿势：waitUntil: 'networkidle0'（网络静默）+ 图表库切到无动画模式（ECharts animation: false）+ 页面里埋一个「渲染完成」标记位供 page.waitForFunction 探测。生产环境还要加单任务超时（60s）防卡死页面拖垮实例池。
</details>

<details>
<summary><b>7. 【挑战】设计一个 SaaS 的报表导出中心：支持 50 万行明细的月报 PDF、导出水印、导出审计，给出完整链路。</b></summary>

链路设计：① 请求层——导出参数（期间/范围/格式）+ 幂等任务 ID（防重复提交，62/63 册思路）；② 任务层——异步队列，50 万行明细走数据库游标流式读取（52 册分页与游标），服务端分块渲染 HTML 分片，无头浏览器按分片追加打印避免单页面内存爆炸；③ 水印层——PDF 每页嵌隐形水印（操作人工号 + 导出时间，pdf-lib 后处理），屏幕预览层显式水印；④ 交付层——生成完成 → 通知中心推送下载链接（62 册），链接带时效与一次性 token；⑤ 审计层——导出动作、下载动作分别记审计（63 册：谁、何时、什么范围、多少行、filterHash）；⑥ 护栏——单租户并发导出数上限、单任务 60s 超时、失败重试三次入死信队列告警。整条链的关键认知：大导出是后台任务不是 HTTP 请求，水印与审计是合规底线不是附加功能。
</details>

<details>
<summary><b>8. 【挑战】用户反馈「导出的 PDF 里中文全是方框」，列出排查路径与根治方案。</b></summary>

排查路径：① 确认生成环境——服务端无头浏览器？容器镜像里有没有装中文字体（fc-list | grep -i cjk）；② 确认字体声明——CSS font-family 是否指定了容器中存在的字体栈；③ 确认编码——HTML 是否声明 UTF-8，数据源字符集是否正确。根治方案：① 容器镜像内置 Noto Sans CJK（或思源黑体）并 fc-cache；② 字体子集化——用 fonttools pyftsubset 按报表实际用字裁剪，10MB 字体压到几百 KB，嵌入 PDF 保可移植性；③ CI 门禁——构建镜像后跑一个中文 PDF 冒烟用例，解析 PDF 文本层断言中文可选中（pdf-parse），字体缺失在 CI 期拦截；④ 回退兜底——字体加载失败时任务直接失败告警，宁可导不出来也不交付豆腐块文件。
</details>

## 65.6 本章避坑清单

| # | 坑 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 让用户直接 Ctrl+P 业务页 | 打印出来支离破碎 | 永远提供专门打印视图 |
| 2 | 依赖 @page margin boxes 页眉页脚 | Chrome 未实现，兼容性不及格 | 页眉页脚需求直接上服务端 PDF |
| 3 | 忽略打印缩放 | 120% 缩放下 mm 定位全失真 | 套打说明锁定 100% 缩放，预览页明示 |
| 4 | 打印样式默认省墨 | 背景色全丢，红字变黑 | print-color-adjust: exact 逐元素决策 |
| 5 | 分页全靠声明式 CSS | 标题孤悬页尾、合计与明细分离 | 装箱算法 + keepWithNext 孤行控制 |
| 6 | 套打模板用 px 定坐标 | 屏幕缩放后与纸张 mm 失配 | 模板域只用 mm，预览时再换算 |
| 7 | 模板不做越界重叠自检 | 错位字打到预印制发票上，实物作废 | 保存期自检（越界/重叠/maxChars），错误左移 |
| 8 | 缺数据字段静默空白 | 发票漏项成财务事故 | missing 清单人工确认，truncated 高亮警告 |
| 9 | 忽略打印机进纸偏差 | 同一模板不同打印机错位 1-2mm | 全局偏移补偿按「打印机+纸张」存配置 |
| 10 | html2canvas 出正式文件 | 文字不可选、放大模糊、体积膨胀 | 正式文件走矢量：pdf-lib 或服务端 PDF |
| 11 | 服务端容器缺中文字体 | 满篇豆腐块交付客户 | 镜像内置 Noto CJK + 字体子集化 + CI 冒烟 |
| 12 | 截图不等渲染完成 | 图表残缺、字体回退 | networkidle0 + 关动画 + waitForFunction 完成标记 |
| 13 | 大导出同步阻塞请求 | 网关超时、重复任务 | 异步任务 + 通知中心下发 + 幂等任务 ID |
| 14 | 导出文件无水印 | 泄漏后无法溯源 | 隐形水印（工号+时间）嵌入 PDF |
| 15 | 导出不记审计 | 数据外发无迹可查 | 导出与下载双审计（范围/行数/filterHash，63 册） |
