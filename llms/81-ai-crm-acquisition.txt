## 81.1 获客全链路总览

### 概念解析

外贸获客不是"找一批邮箱群发"，而是一条有漏斗的链路：

```
公海客户(海量)
    │ ICP 评分 + AI 排序
    ▼
目标客户池(Top N)
    │ 多维筛选（行业/规模/地区/营收）
    ▼
待触达客户
    │ 联系方式获取 + 合规校验
    ▼
可触达客户
    │ CRM 录入 + 阶段推进
    ▼
线索 → 商机 → 成交
```

前端在这条链路里的核心工作：**把海量数据变成可操作的列表**——评分排序、筛选条件、联系方式状态、CRM 阶段，每一步都要有清晰的 UI 反馈。

### 应用实践

- **获客效率看转化率**，不是看线索数量。100 条 ICP 匹配度 80+ 的线索，比 10000 条盲打线索值钱；
- **每一步都要能"为什么"**：客户卡片要展示 ICP 评分的拆解（行业✓ 规模✓ 地区✗ 营收✓），让销售知道"为什么这个客户值得跟"。

## 81.2 ICP 理想客户画像与 AI 评分

### 概念解析

ICP（Ideal Customer Profile，理想客户画像）是"我们最想服务的客户长什么样"。外贸场景下通常包含：行业、公司规模、地区、年营收、技术栈匹配度等。

AI 评分的本质：**把客户属性与 ICP 画像做匹配，输出 0~100 的匹配度分数**。四维各 25 分，命中满分，部分命中按比例衰减。这样销售一眼就知道"该先跟谁"。

### 完整代码示例

```ts
// 文件: examples/81-01-crm-customer-pipeline.ts（节选：ICP 评分）
export function icpScore(customer: Customer, icp: ICPProfile): number {
  let score = 0;
  score += icp.industries.includes(customer.industry) ? 25 : 0;
  const [min, max] = icp.employeeRange;
  if (customer.employees >= min && customer.employees <= max) score += 25;
  else {
    const dist = customer.employees < min ? min - customer.employees : customer.employees - max;
    score += Math.max(0, 25 - Math.floor(dist / 10));
  }
  score += icp.regions.includes(customer.region) ? 25 : 0;
  score += Math.min(25, Math.floor((customer.revenue / icp.minRevenue) * 25));
  return score;
}
```

### 应用实践

- **评分要可解释**：不要只给一个总分，要展示每一项的得分（行业 25/25、规模 20/25…）。销售需要知道"差在哪"才能决定要不要补全信息；
- **评分可以 AI 增强**：基础规则评分之外，AI 可以分析客户官网、新闻、融资情况做"软匹配"加分项，但这部分要标"AI 推测"，不能与硬事实混在一起；
- **评分阈值决定动作**：≥75 分自动进入"高优跟进"，50~74 分"常规培育"，<50 分"暂不触达"。阈值要可配置，不同产品线 ICP 不同。

## 81.3 客户搜索与多维筛选

### 概念解析

客户列表是 CRM 的核心操作界面。外贸获客的筛选维度比普通后台多——除了行业、规模、地区，还有：

- **联系方式状态**：有邮箱 / 有电话 / 无联系方式；
- **ICP 评分区间**：只看 75 分以上的；
- **最近活动**：30 天内有互动 / 超过 90 天未跟进；
- **阶段**：lead / prospect / qualified。

筛选的工程要点：**条件组合 AND**、**结果可保存为视图**、**筛选条件可分享（URL 化）**。

### 完整代码示例

```ts
// 文件: examples/81-01-crm-customer-pipeline.ts（节选：多维筛选）
export interface FilterCondition {
  field: keyof Customer;
  op: "eq" | "in" | "gte" | "lte" | "between" | "contains";
  value: unknown;
}

export function filterCustomers(customers: Customer[], conditions: FilterCondition[]): Customer[] {
  return customers.filter((c) =>
    conditions.every((cond) => { /* 按 op 分发判断 */ }),
  );
}
```

### 应用实践

- **筛选条件 URL 化**：把当前筛选序列化成 query string 放进 URL，刷新不丢、可分享给同事。大型列表页这是标配；
- **已选条件可视化**：筛选后顶部展示"已选条件"标签组，每个可单独移除，比让用户回筛选器里找更直观；
- **大数据量走服务端筛选**：客户数据动辄几万条，筛选、排序、分页都在服务端做，前端只传条件（见 [52 册 BFF 数据层](./52-database-bff.md)）。

## 81.4 联系方式获取与合规

### 概念解析

有了目标客户，下一步是找到能联系上的人。AI 获客工具会从公开渠道（官网、LinkedIn、展会数据）和第三方数据源补全联系方式。但这里有**红线**：

- **合规来源**：GDPR / CAN-SPAM / 中国《个人信息保护法》都要求营销触达需有合法依据。必须标记联系方式的来源（公开 / 补全 / 人工）和合规状态；
- **未合规的联系方式不能用于营销**：可以展示在客户卡片上，但不能加入群发队列；
- **退订机制**：营销邮件必须带退订链接，退订后该联系方式标记为 `compliant: false`。

### 完整代码示例

```ts
// 文件: examples/81-01-crm-customer-pipeline.ts（节选：联系方式合规）
export function isContactCompliant(contact: ContactInfo | undefined): boolean {
  if (!contact) return false;
  return contact.compliant && (contact.source === "public" || contact.source === "enrichment");
}
```

### 应用实践

- **联系方式状态用颜色标记**：合规的绿色可用，待校验的黄色提示，不合规的红色禁用群发按钮；
- **补全操作要透明**：AI 补全联系方式后，要展示"来源：LinkedIn 公开数据"，让销售知道信息从哪来，可信度如何；
- **批量补全要有配额和审计**：第三方补全 API 按次收费，批量补全要显示配额消耗、补全成功率，每条补全写审计。

## 81.5 CRM 客户列表与阶段推进

### 概念解析

CRM 的核心是**销售漏斗**：lead（线索）→ prospect（意向）→ qualified（确认需求）→ won（成交）/ lost（流失）。每个阶段有准入条件——比如进入 qualified 必须已有联系方式、已确认预算。

阶段推进是**有向状态机**，不能跳步（lead 不能直接到 won），终态（won/lost）不可再推进。

### 完整代码示例

```ts
// 文件: examples/81-01-crm-customer-pipeline.ts（节选：CRM 阶段）
export const CRM_STAGE_TRANSITIONS = {
  lead: ["prospect", "lost"],
  prospect: ["qualified", "lost"],
  qualified: ["won", "lost"],
  won: [],
  lost: [],
};

export function advanceStage(customer: Customer, to: Customer["stage"]): Customer {
  if (!canAdvanceStage(customer.stage, to)) throw new Error("非法阶段迁移");
  if (to === "qualified" && !customer.hasContact) {
    throw new Error("进入 qualified 阶段必须先获取联系方式");
  }
  return { ...customer, stage: to };
}
```

### 应用实践

- **看板视图 + 列表视图切换**：销售喜欢看板（拖拽换阶段），管理者喜欢列表（批量操作）。两种视图共享同一份数据，切换不丢筛选；
- **阶段推进要留跟进记录**：每次改阶段强制写一条跟进备注（为什么进 prospect、客户说了什么）。没有跟进记录的阶段推进不允许保存；
- **SLA 提醒**：每个阶段有最大停留时间（如 prospect 超过 30 天未推进标黄提醒），防止线索躺着没人跟。

## 81.6 自测题

<details>
<summary><b>1. 【基础】ICP 评分为什么要可解释，不能只给一个总分？</b></summary>

销售需要知道"为什么这个客户值得跟"以及"差在哪"。只给总分无法决策——是行业不匹配还是规模不够？可解释的评分（每项得分拆解）让销售知道要不要补全信息、是否值得投入精力。
</details>

<details>
<summary><b>2. 【进阶】为什么筛选条件要 URL 化？</b></summary>

三个好处：① 刷新页面不丢筛选条件；② 可分享给同事（"你看看这批客户"）；③ 可保存为个人视图（销售有自己常用的筛选组合）。实现方式是把筛选序列化成 query string，页面加载时从 URL 反序列化。
</details>

<details>
<summary><b>3. 【进阶】为什么未合规的联系方式不能用于营销？</b></summary>

GDPR / CAN-SPAM / 《个人信息保护法》要求营销触达需有合法依据。不合规的联系方式（来源不明、未校验、用户已退订）用于营销会面临罚款和投诉。所以系统层面要拦截：未合规的联系方式展示但禁用群发按钮。
</details>

<details>
<summary><b>4. 【挑战】CRM 阶段推进为什么要有准入条件？</b></summary>

如果阶段可以随便跳，销售漏斗就失去了管理意义——lead 直接标 won，数据全是假的。准入条件（如进 qualified 必须有联系方式）保证每个阶段都有实质进展，漏斗数据才可信。阶段推进还是有向状态机，不能跳步、终态不可改。
</details>

| 场景 | 高频坑 | 一句话避法 |

## 81.8 面试问答

<details>
<summary><b>【L2】AI 获客系统里，ICP 评分怎么设计？为什么要可解释？</b></summary>

**回答框架**：① ICP = 理想客户画像（行业/规模/地区/营收等维度）；② 评分 = 各维度加权求和（如行业25+规模25+地区25+营收25）；③ 可解释 = 展示每项得分拆解，让销售知道"差在哪"。不能只给总分，否则销售无法判断要不要补全信息、值不值得投入。

**评分要点**：评分维度合理；加权计算正确；能说出可解释的原因。

**加分项**：提到 AI 软匹配加分项（官网/新闻分析）要标"AI 推测"与硬事实分开；提到评分阈值决定动作（≥75 高优跟进）。
</details>

<details>
<summary><b>【L3】客户列表有 10 万条数据，前端筛选+分页+排序怎么设计？</b></summary>

**回答框架**：① 服务端做筛选/排序/分页，前端只传条件（industry in [...]、employees >= 50、page=2、pageSize=20、sortBy=score desc）；② 筛选条件 URL 化，刷新不丢、可分享；③ 已选条件可视化（顶部标签组可移除）；④ 大数据量下用虚拟列表渲染可见区。

**评分要点**：知道筛选/排序/分页走服务端；提到 URL 化；提到已选条件展示。

**加分项**：提到保存为个人视图；提到虚拟滚动（见 64 册）；提到服务端用索引优化（ICP 评分、行业、地区建联合索引）。
</details>

<details>
<summary><b>【L2】AI 补全了客户联系方式，为什么还要做合规校验？不合规的怎么处理？</b></summary>

**回答框架**：① 法规要求（GDPR/CAN-SPAM/个保法）营销触达需合法依据；② 联系方式要标记来源（公开/补全/人工）和合规状态；③ 不合规的展示但禁用群发按钮；④ 补全要展示来源建立可信度。

**评分要点**：能说出法规依据；知道来源和合规状态标记；知道不合规的处理（禁用群发）。

**加分项**：提到退订机制；提到批量补全的配额和审计；提到不同地区法规差异（欧盟 GDPR 最严）。
</details>

<details>
<summary><b>【L3】销售把一个 lead 直接拖到 won，前端应该怎么拦截？为什么？</b></summary>

**回答框架**：① CRM 阶段是有向状态机，不能跳步（lead→prospect→qualified→won）；② 拖拽时 canMoveTo 守卫拦截非法迁移；③ 每个阶段有准入条件（进 qualified 必须有联系方式，进 won 必须有成交金额）；④ 拦截后提示"请先推进到 prospect 阶段"。这样保证漏斗数据真实可信，不会出现 lead 直接标 won 的假数据。

**评分要点**：知道阶段是有向状态机不能跳步；提到准入条件；提到守卫拦截。

**加分项**：提到阶段推进强制写跟进备注；提到 SLA 提醒（阶段停留超时）；提到管理者可看漏斗转化率。
</details>
