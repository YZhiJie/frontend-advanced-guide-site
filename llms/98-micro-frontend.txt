## 98.1 微前端核心思想与应用注册

### 概念解析

微前端 = **微服务思想在前端的落地**：把大型前端应用拆成多个子应用，每个子应用可独立开发、独立部署、独立运行，由主应用（基座）统一调度。

子应用生命周期（single-spa 规范）：
- `bootstrap`：首次加载前初始化（只执行一次）
- `mount`：挂载到 DOM，渲染子应用
- `unmount`：卸载，清理 DOM、事件、定时器

```ts
// 子应用入口
export async function bootstrap() { /* 初始化 */ }
export async function mount(props) {
  ReactDOM.createRoot(props.container).render(<App />);
}
export async function unmount(props) {
  ReactDOM.createRoot(props.container).unmount();
}
```

### 完整代码示例

```ts
// 文件: examples/98-01-micro-frontend.ts（节选：注册与路由）
class MicroFrontendRegistry {
  register(app: MicroApp) { this.apps.set(app.name, app); }
  async route(location: string) {
    for (const app of this.apps.values()) {
      if (app.activeWhen(location)) {
        await this.unmount(this.current); // 先卸载旧应用
        await app.lifecycle.mount({ container: `#${app.name}` });
        this.current = app.name;
      }
    }
  }
}
```

> 运行方式：`npx tsx examples/98-01-micro-frontend.ts`

### 应用实践

- **路由分发**：主应用监听 `popstate`/`hashchange`，根据路径激活对应子应用
- **HTML Entry**：qiankun 通过 `fetch` 拉取子应用 HTML，解析 JS/CSS 后执行
- **独立部署**：每个子应用是独立仓库，构建产物部署到自己的 CDN，主应用通过 entry URL 加载

## 98.2 JS 沙箱：全局变量隔离

### 概念解析

子应用可能往 `window` 上挂全局变量、定时器、事件监听，多个子应用切换时会互相污染。**JS 沙箱**用 `Proxy` 代理 window，把子应用的写入拦截到私有副本。

```ts
const fakeWindow = {};
const proxy = new Proxy(fakeWindow, {
  get(target, prop) {
    return prop in target ? target[prop] : window[prop]; // 私有优先，回退真实
  },
  set(target, prop, value) {
    target[prop] = value; // 写入只进私有副本
    return true;
  },
});
```

### 完整代码示例

```ts
// 文件: examples/98-01-micro-frontend.ts（节选：Proxy 沙箱）
class JSSandbox {
  private fakeWindow = {};
  createProxy() {
    return new Proxy(this.fakeWindow, {
      get: (t, p) => p in t ? t[p] : this.originalWindow[p],
      set: (t, p, v) => { t[p] = v; return true; },
    });
  }
}
```

### 应用实践

| 沙箱类型 | 原理 | 适用 |
|---|---|---|
| **快照沙箱** | 进入子应用前快照 window，退出时还原 | 单实例 |
| **Proxy 沙箱** | 用 Proxy 代理 window 读写 | 多实例（qiankun 默认） |
| **iframe 沙箱** | 子应用跑在 iframe 里 | wujie，隔离最彻底 |

- **卸载清理**：子应用 unmount 时要清定时器 `clearInterval`、移除事件监听 `removeEventListener`，否则内存泄漏
- **全局变量冲突**：子应用不要往 window 挂变量，用沙箱私有域或模块化导出

## 98.3 样式隔离

### 概念解析

子应用的 CSS 可能污染主应用或其他子应用（如 `.btn { color: red }` 全局生效）。隔离方式：

1. **CSS 作用域前缀**：给子应用所有选择器加前缀（如 `#app-order .btn`）
2. **Shadow DOM**：把子应用挂在 shadow root 里，样式天然隔离
3. **CSS Modules**：构建时哈希化类名
4. **iframe**：wujie 用 iframe，样式完全隔离

### 完整代码示例

```ts
// 文件: examples/98-01-micro-frontend.ts（节选：样式前缀）
function scopeCSS(css, prefix) {
  return css.replace(/([^{]+)\{/g, (_, sel) => {
    const scoped = sel.split(",").map(s => `${prefix} ${s.trim()}`).join(",");
    return `${scoped} {`;
  });
}
```

### 应用实践

- **qiankun**：默认用 `experimentalStyleIsolation`（scoped），严格隔离用 `strictStyleIsolation`（shadow DOM）
- **Module Federation**：靠 CSS Modules 或约定类名前缀，无内置隔离
- **注意点**：`position: fixed` 在 shadow DOM 中相对 shadow root 而非视口，可能错位；全局样式（如 `body`）在 shadow DOM 内不生效

## 98.4 三种方案对比与选型

### 概念解析

| 方案 | 实现原理 | JS 沙箱 | CSS 隔离 | 独立部署 | 最佳场景 |
|---|---|---|---|---|---|
| **qiankun** | HTML Entry + single-spa | Proxy 快照 | scoped | ✅ | 多技术栈、存量应用多 |
| **Module Federation** | Webpack/Rspack 运行时远程加载 | 无 | 自行处理 | ✅ | 同技术栈、新应用 |
| **wujie** | Web Components + iframe | iframe | iframe | ✅ | 老旧应用、需强隔离 |

### 完整代码示例

```ts
// 文件: examples/98-01-micro-frontend.ts（节选：选型）
function selectSolution(scene) {
  if (scene.legacyApps) return "wujie";           // 老旧应用 iframe 最稳
  if (scene.multiTech) return "qiankun";          // 多技术栈 qiankun 成熟
  return "module-federation";                     // 同技术栈 MF 最自然
}
```

### 应用实践

- **qiankun**：基于 single-spa，国内生态成熟，文档中文全，适合 Vue/React 混合
- **Module Federation**：Webpack 5 原生能力，子应用间可共享组件/依赖，适合同技术栈团队
- **wujie**：腾讯出品，用 iframe 实现强隔离，改造成本最低，适合老旧系统嵌入
- **选型决策树**：是否有老旧应用 → wujie；是否多技术栈 → qiankun；同技术栈新项目 → MF

## 98.5 通信机制与公共依赖

### 概念解析

子应用之间、主应用与子应用之间需要通信。三种方式：

1. **Props 下发**：主应用通过 mount props 传数据（适合初始化）
2. **全局事件总线**：发布订阅模式（适合跨应用事件）
3. **全局状态管理**：主应用维护共享 store，子应用通过 props 或 SDK 访问

### 完整代码示例

```ts
// 文件: examples/98-01-micro-frontend.ts（节选：事件总线）
class GlobalEventBus {
  on(event, cb) { /* 订阅 */ }
  emit(event, data) { /* 发布 */ }
}
```

### 应用实践

- **公共依赖**：React/Vue/axios 等大依赖通过 MF `shared` 共享，或主应用 externals 后子应用复用，减少重复加载
- **登录态**：主应用统一管理 token，通过 props 或全局变量传给子应用
- **样式主题**：主应用定义 CSS 变量（`--primary-color`），子应用引用，实现主题统一
- **通信约定**：事件名加应用前缀（`order:created`），避免命名冲突

## 98.6 自测题

<details>
<summary>1. 微前端子应用的生命周期有哪几个？分别在什么时机执行？</summary>

`bootstrap`（首次加载前初始化，只执行一次）→ `mount`（路由匹配时挂载渲染）→ `unmount`（路由切换时卸载清理）。基于 single-spa 规范，每个生命周期都返回 Promise。
</details>

<details>
<summary>2. JS 沙箱的 Proxy 方案是怎么隔离全局变量的？为什么子应用能读到主应用的全局变量？</summary>

用 Proxy 代理一个空对象作为 fakeWindow，`set` 时写入 fakeWindow（不污染真实 window），`get` 时先查 fakeWindow，查不到再回退真实 window。这样子应用的写入隔离，但能读取主应用的全局变量（如 location、document）。
</details>

<details>
<summary>3. qiankun、Module Federation、wujie 三种方案的核心区别是什么？</summary>

qiankun 基于 single-spa + HTML Entry，用 Proxy 沙箱和 scoped 样式，适合多技术栈；MF 是 Webpack 运行时远程加载，无内置沙箱靠 CSS Modules，适合同技术栈；wujie 用 iframe + Web Components，隔离最彻底，适合老旧应用。
</details>

<details>
<summary>4. 微前端的样式隔离有哪些方式？shadow DOM 有什么坑？</summary>

方式：CSS 作用域前缀、Shadow DOM、CSS Modules、iframe。shadow DOM 的坑：`position: fixed` 相对 shadow root 而非视口；全局 `body` 样式不生效；表单元素的 focus 行为可能异常。
</details>

<details>
<summary>5. 微前端子应用之间怎么通信？公共依赖怎么处理？</summary>

通信：主应用通过 mount props 下发数据、全局事件总线发布订阅、共享 store。公共依赖：MF 用 `shared` 配置共享 React/Vue 等，或主应用 externals 后子应用通过全局变量复用，避免重复加载。
</details>

## 98.7 本章避坑清单

| 场景 | 高频坑 | 一句话避法 |
|---|---|---|
| 内存泄漏 | 切换子应用后定时器还在跑 | unmount 里清所有 setInterval/setTimeout、removeEventListener |
| 全局污染 | 子应用挂 window 变量冲突 | 用沙箱私有域，不要往 window 挂业务变量 |
| 样式冲突 | 子应用 CSS 覆盖主应用 | 开 strictStyleIsolation 或 CSS Modules，类名加应用前缀 |
| 路由冲突 | 子应用路由和主应用冲突 | 子应用用相对路由，主应用统一管理 basename |
| 资源加载 | 子应用静态资源 404 | 子应用构建时设 `publicPath`，qiankun 会自动修正相对路径 |
| 重复加载 | 多个子应用都打包了 React | 用 MF shared 或 externals 共享公共依赖 |
| 通信混乱 | 事件名冲突 | 事件名加应用前缀（`order:created`），建立通信约定 |
