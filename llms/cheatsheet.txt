## 事件循环判定

| 场景 | 归属 | 顺序 |
| ---- | ---- | ---- |
| 同步代码、`console.log` | 调用栈 | 最先 |
| `Promise.then/finally`、`await` 之后、`queueMicrotask` | **微任务** | 当前轮全部清空 |
| `setTimeout/setInterval`、I/O、UI 事件 | **宏任务** | 每轮只取一个 |

> 口诀：**同步跑完 → 微任务清空 → 一个宏任务 → 循环**。详见 [1.5](./01-javascript-advanced.md#_1-5-异步编程与事件循环)。

## 防抖 vs 节流

| | 防抖 debounce | 节流 throttle |
|--| ------------ | ------------- |
| 行为 | 停止触发 N ms 后执行一次 | 每 N ms 最多执行一次 |
| 记忆 | **等停止** | **匀速跑** |
| 场景 | 搜索联想、resize 完成 | 滚动加载、按钮防连点 |

详见 [1.8](./01-javascript-advanced.md#_1-8-手写高频工具函数)。

## 缓存决策

```
带内容哈希的静态资源  → Cache-Control: max-age=31536000, immutable   (强缓存一年)
HTML / 入口文档       → Cache-Control: no-cache                       (每次协商)
实时数据(余额/库存)   → no-store
低频变化的数据        → 短 max-age + stale-while-revalidate
```

> 黄金法则:**HTML 不强缓存,指纹资源强缓存**。详见 [6.2](./06-network.md#_6-2-缓存策略详解)、SW 可编程层见 [10.6](./10-browser-rendering.md#_10-6-service-worker-与-pwa)。

## 竞态处理三招（优先级从高到低）

1. **取消旧请求**：`AbortController`（搜索、筛选必配）；
2. **忽略过期结果**：版本号/标志位比对；
3. **防抖**：减少触发频率（只能缓解，需与前两者组合）。

详见 [6.5](./06-network.md#_6-5-竞态处理与请求取消)。

## 原理地基速查

**JS 执行管线（1.1）**：源码 → 词法分析(token) → 语法分析(AST) → 字节码(Ignition/TurboFan) → 执行上下文创建（`var`→undefined、`let/const`→TDZ）→ 逐行执行。`SyntaxError` 解析期全段不执行，`ReferenceError` 执行期才抛。Babel/ESLint/SWC 都是 AST 改写。

**首次渲染管线（10.1）**：HTML→DOM 树 · CSS→CSSOM 树 → 渲染树（`display:none` 不入树、`visibility:hidden` 占位）→ Style → Layout → Paint → Composite。JS 阻塞解析（用 `defer`），CSS 阻塞渲染（关键 CSS 内联）。

**盒模型与 margin（12.1）**：`content-box` 占位=width+padding+border；`border-box` 占位恒=width（reset 全局设）。垂直相邻 margin 合并取 `max`；父子 margin 穿透用 `display:flow-root` 隔断；flex/grid 子项不合并。

## TypeScript 三件套

```typescript
type Pick      <T, K extends keyof T> = { [P in K]: T[P] }              // 挑键
type Exclude   <T, U>                 = T extends U ? never : T         // 拆联合(分布式)
type ReturnType<T>                    = T extends (...a: never[]) => infer R ? R : never  // infer 捕获
```

> 手写顺序:Partial → Pick → Omit → ReturnType → DeepReadonly。详见 [2.5](./02-typescript.md#_2-5-手写常用工具类型)。

## 浏览器新能力速查（17.1）

| 能力 | 一句话用法 | 替代了什么 |
| ---- | ---------- | ---------- |
| **Popover API** | `<div popover>` + `popovertarget=xx` | 手写 z-index 大战 + 全局点击监听 |

## Web Components 三件套速查（17.3）

| 能力 | 关键 API/属性 | 坑点 |
| ---- | ------------- | ---- |
| Custom Elements | `customElements.define`、`observedAttributes`、`connectedCallback` | `disconnectedCallback` 不止一次（元素可能反复挂/卸） |
| Shadow DOM | `attachShadow({mode:'open'})` | 内部事件外发需 `composed:true` |
| Slot 组合 | `<slot name=xx>` + `<slot>` 默认 | 内容仍在光 DOM，只是渲染位置被组件控制 |
| 声明式 Shadow DOM | `<template shadowrootmode="open">` | JS 再调 `attachShadow` 会报错 → 用 `this.shadowRoot ??` 检测 |
| Lit | `@customElement` + `@property` + `html` 模板 | 自动处理响应式/属性反射/Shadow DOM，样板代码消 80% |

> 选 WC 的信号：跨框架/跨团队/跨应用复用（设计系统、微前端）。React 19 已原生支持自定义元素属性/事件映射。详见 [17.3](./17-web-platform.md#_17-3-web-components)。

## WASM 适用边界（17.4）

```
先 Profiler 定位热点 → 纯计算(图像/编解码/加密) → 有现成 C/C++/Rust 实现可复用?
   是 → 编译为 WASM（5~20x 提速）    否 → JS 优化 + Web Worker 可能足够
   ❌ 操作 DOM → 反模式（边界穿越开销抵消优势）
```

| 维度 | AssemblyScript | Rust + wasm-pack |
| ---- | -------------- | ---------------- |
| 上手 | TypeScript 子集 | Rust（曲线陡） |
| 性能 | 接近原生（略慢） | 最优 |
| 生态 | 小 | 大（crates.io） |
| 适用 | 原型验证 | 生产级 |

> 生产用法：WASM 跑在 Worker 中，主线程通过 Transferable 零拷贝传 ArrayBuffer；批量传递整帧而非逐像素，减少 JS↔WASM 边界穿越。详见 [17.4](./17-web-platform.md#_17-4-webassembly-适用边界)。

## Worker 三兄弟选型

| 维度 | DedicatedWorker | SharedWorker | ServiceWorker |
| ---- | --------------- | ------------ | ------------- |
| 归属 | 单个页面独占 | 同源多 Tab 共享一个实例 | 浏览器级代理,与页面解耦 |
| 生命周期 | 页面关闭 / `terminate()` 即毁 | 所有 port 关闭后可回收 | 安装后持久;空闲挂起、事件唤醒 |
| 拦截 fetch | ❌ | ❌ | ✅(核心能力) |
| 典型用途 | 计算卸载、大 JSON/像素处理 | 单 WebSocket 复用、跨 Tab 状态 | 离线缓存、Push、后台同步 |
| 全局变量 | 存活期可靠 | 存活期跨页共享 | ❌ 不可靠,状态落 IDB/Cache |

**postMessage 数据传递三招**：

| 方式 | 成本 | 要点 |
| ---- | ---- | ---- |
| 结构化克隆(默认) | 深拷贝,大对象贵 | 不支持函数/DOM/原型链 |
| Transferable | 零拷贝转移 | `postMessage(m, [buf])`,发送方立即 detached |
| SharedArrayBuffer | 共享内存 | 需 COOP+COEP 头(`crossOriginIsolated`),配 `Atomics` |

> Worker 路径统一写 `new Worker(new URL('./x.worker.ts', import.meta.url), { type: 'module' })`;常驻 + 池化复用,切路由记得 `terminate()`。详见 [模块二](./18-worker-messaging.md#模块二-dedicatedworker-web-worker-详解) / [模块三](./18-worker-messaging.md#模块三-sharedworker-共享线程详解) / [10.5](./10-browser-rendering.md#_10-5-web-worker-计算卸载)。

## Service Worker 一页纸

```
生命周期: install(预缓存) → waiting(skipWaiting 跳过) → activate(清旧缓存 + clients.claim)
铁律:     异步操作一律 event.waitUntil() 续期;无 DOM、无 localStorage;随时被挂起
更新:     sw.js 逐字节变化才触发;发现新版 → 提示 → postMessage('SKIP_WAITING')
          → controllerchange → location.reload();上线必备"自毁 SW"回滚预案
```

| 资源类型 | 缓存策略 |
| -------- | -------- |
| 带 hash 静态资源 | Cache First(+ 运行时回填) |
| HTML / 导航请求 | Network First(失败回退缓存 / offline.html) |
| 可容忍短暂过期 | Stale While Revalidate |
| 实时接口 / 写入请求 | Network Only,不缓存 |

详见 [模块五](./18-worker-messaging.md#模块五-serviceworker-详解) / [10.6](./10-browser-rendering.md#_10-6-service-worker-与-pwa)。

## 跨 Tab 通信选型

| 场景 | 方案 | 关键注意 |
| ---- | ---- | -------- |
| 同源多 Tab 广播 | **BroadcastChannel**(首选) | 自己收不到、无持久化 |
| 广播 + 新 Tab 状态初始化 | `localStorage` + storage 事件 | 自己收不到;相同值不触发,消息带时间戳;约 5MB |
| 弹窗 / iframe(可跨源) | `window.postMessage` | 收发双方都校验 origin,发送禁用 `'*'` |
| 全浏览器单连接 / 共享状态 | SharedWorker 总线 | URL+name 逐字符一致才是同一实例;心跳清僵尸 port |
| Leader 选举 / 互斥 | Web Locks API | Leader 崩溃锁自动释放,无需心跳 |
| 大数据共享 | IndexedDB + BroadcastChannel 通知 | IDB 无变更事件,只传 id 不传正文 |
| 跨设备 / 跨浏览器 | WebSocket / SSE 服务端中转 | 配合 Web Locks 只让 Leader 建一条连接 |

> MessagePort 用 `addEventListener('message')` 必须手动 `port.start()`(赋 `onmessage` 会隐式启动);ServiceWorker 中继用 `clients.matchAll()` 遍历,或直接在 SW 内用 BroadcastChannel。详见 [模块四](./18-worker-messaging.md#模块四-messagechannel-messageport-端口通信) / [模块六](./18-worker-messaging.md#模块六-跨-tab-窗口通信全方案),18 条坑点见 [模块十](./18-worker-messaging.md#模块十-坑点速查、调试与自测)。

## 模式识别与架构速查

| 看到什么坏味道 | 上什么模式 |
| -------------- | ---------- |
| if-else / switch 长链 | 策略（查表注册） |
| 布尔标志位组合（loading && !error && …） | 状态机（互斥状态 + 显式转移） |
| 撤销/重做需求 | 命令（do/undo 双栈；新操作清空 redo 栈） |
| 全局唯一（弹窗/Toast/store） | 单例（闭包 + 惰性创建） |
| 重复请求 / 懒加载 / 控制访问 | 代理（缓存 + 去重） |
| 多渠道异构 SDK | 适配器（业务只认抽象） |
| 跨模块多对多通知 | 发布订阅（on 返回解绑函数,卸载必调） |

**监控上报三件套**：`sendBeacon`（hidden 兜底 flush）+ 采样限流（防自拖垮）+ 指纹聚合（message + stack 前两帧去行列号）。上报数据必带 sessionId / release / 环境。详见 [11.2](./11-patterns-architecture.md#_11-2-前端监控与错误上报)。

**微前端选型**：多栈存量聚合 → qiankun｜重隔离（不可信代码）→ wujie/iframe｜同栈大团队共享依赖 → Module Federation（防双框架实例）｜其余 90% 需求 → 别上微前端，Monorepo + 路由懒加载。详见 [11.3](./11-patterns-architecture.md#_11-3-微前端概览)。

**分层铁律**：视图 → 业务 → 服务 → 基建，依赖只许自上而下；目录按功能域分（删除一个功能 = 删一个目录）；组件设计 = 受控/非受控双模 + 组合优于配置 + Headless 拆逻辑。详见 [11.4](./11-patterns-architecture.md#_11-4-前端架构设计方法)。

## 测试金字塔与选型速查

```
        ╭─ E2E (≤20 条) ╮       关键用户路径,Playwright
       ╭┤  集成/组件    ├╮      Testing Library 性价比最高
      ╭ └────────────── ┘╰╗     Vitest 单测(纯函数/hooks/store)
     ╰──────────────────────╯   类型测试/ESLint 零运行成本
```

| 看到这个代码 | 该写什么测试 |
| ------------ | ------------ |
| 纯函数（金额计算、解析、深拷贝） | Vitest 单测，参数化 it.each + 异常分支 |
| 自定义 Hook / composable | Vitest 单测 + 必要时 jsdom |
| UI 组件（有交互/异步） | Testing Library + userEvent + MSW |
| 关键用户路径（登录/下单/支付） | Playwright E2E，限制 ≤20 条 |
| 导出给他人用的库 | tsd 类型测试 + tsc --noEmit |
| 配置文件/纯文案 | 静态检查 + Review，不写测试 |

## Testing Library 查询优先级

```
getByRole > getByLabelText > getByPlaceholderText > getByText
       > getByDisplayValue > getByAltText > getByTitle > getByTestId
```

| 前缀 | 行为 | 不匹配时 |
| ---- | ---- | -------- |
| `getBy*` | 同步取一个 | 抛错（同步断言用） |
| `queryBy*` | 同步取一个 | 返回 null（断言"不存在"用） |
| `findBy*` | 异步等一个 | 超时抛错（异步出现的元素用） |

| 场景 | API |

| 需求 | 选择 |
| ---- | ---- |

## 迭代协议与惰性管线

```
iterable  [Symbol.iterator]() → iterator { next(): {value,done}, return()? }
generator function*  —— 双协议自动实现;yield 暂停、yield* 委托、next(x) 回灌"上一条 yield"
异步版   async function* + Symbol.asyncIterator + for await...of
yield*   委托内层序列;表达式值 = 内层 return 值(for...of 拿不到);break 沿委托链逐层触发 return()
高阶模式 yield* 递归遍历树(惰性剪枝) / it.throw() 暂停点注入 / next(x) 消费者驱动背压 / yield* next() 洋葱模型
ES2025   Iterator.from(xs).map().filter().take(n).toArray()  // 无中间数组,可喂无限序列
```

> 有状态的迭代器只能消费一次，要可重复遍历就实现 iterable 工厂；持资源必须实现 `return()`。详见 [1.14](./01-javascript-advanced.md#_1-14-iterator、generator-与惰性管线)。

## 正则高级用法速查

```
量词  贪婪 * + ? {m,n} ←加?变惰性→ *? +? ?? {m,n}?   贪婪先吃满再回吐,惰性满足即停
分组  (x)捕获   (?:x)只分组不存   (?<n>x)命名 → m.groups.n
引用  匹配侧 \1 数字 / \k<n> 命名;replace 侧 $1 / $<n>   引"实际匹配到的文本",成对结构靠它
断言  (?=x)右满足  (?!x)右不满足  (?<=x)左满足  (?<!x)左不满足   零宽只看不吃的"位置条件"
```

| 场景 | 正则 |
| ---- | ---- |
| 千分位 | `'12345678'.replace(/\B(?=(\d{3})+(?!\d))/g, ',')` → 12,345,678 |
| 密码强度（大小写+数字、≥8 位） | `/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)\S{8,}$/`（并列 `(?=)` = AND） |
| 成对标签 / 配对引号 | `/<(h[1-6]\|b)>(.*?)<\/\1>/g`、`/(?<q>["']).*?\k<q>/g` |
| 取前缀后的值 | `/(?<=\$)\d+/g` 提取 `$100` 的 100（JS 后行断言支持变长） |

> 贪婪遇嵌套会越界吞并（`<.+>` 吃到行尾最后 `>`），截取用惰性或排除类 `[^>]+`；负向先行挡不住回溯截尾（`'100元'.match(/\d+(?!元)/g)` 得 `['10']`）；嵌套量词 `(a+)+` 是 ReDoS 炸弹。详见 [1.15](./01-javascript-advanced.md#_1-15-正则高级用法)。

### RxJS 拍平操作符选型

```
switchMap   新事件到来 → 取消上一个内层流   搜索联想 / 路由参数 / 自动保存（只关心最新）
concatMap   排队串行，前一个完成再发下一个   下单 / 顺序上传（保序、不可并发）
mergeMap   并发执行，不保证顺序           批量请求 / 并行上传（要并发）
exhaustMap  内层未完成时忽略新事件         提交按钮防重复 / 登录（忙时丢弃）
```

```ts
import { fromEvent, debounceTime, map, switchMap, catchError, of, takeUntil } from 'rxjs';

const search$ = fromEvent<InputEvent>(input, 'input').pipe(
    debounceTime(300),
    map((e) => (e.target as HTMLInputElement).value.trim()),
    switchMap((kw) => api.search(kw).pipe(catchError(() => of([])))), // 旧请求自动取消
    takeUntil(destroy$), // 组件销毁必须收口，否则订阅泄漏
);
const sub = search$.subscribe(render);
// sub.unsubscribe() / destroy$.next() 二选一
```

> 冷流每次订阅都重新执行；多订阅共享结果用 `shareReplay({ bufferSize: 1, refCount: true })`。详见 [29](./29-rxjs.md)。
